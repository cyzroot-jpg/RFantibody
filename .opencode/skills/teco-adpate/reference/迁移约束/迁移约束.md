迁移约束
更新时间：2026-07-08 09:37:06
开源PyTorch上训练的模型支持在CUDA和CPU设备上运行。如果使用TecoPyTorch在太初AI加速卡运行开源PyTorch上训练好的模型，需要将模型脚本中的CUDA设备接口改为SDAA设备接口。  

TecoPyTorch的SDAA接口与开源PyTorch的CUDA接口一一对应，您只需在原始模型脚本中导入TecoPyTorch的功能模块，并将设备相关接口的中cuda全部替换为sdaa，便可完成PyTorch模型在太初AI加速卡上的开发、训练以及调试。 

本文主要介绍模型迁移时的限制约束和注意事项，包含以下几个方面。

适配第三方库
如果原始模型脚本中，调用了模型第三方库，且第三方库使用的是GPU，迁移过程可能会存在适配问题，请联系太初技术人员进行支持。

说明： 
当前SDAA已支持的三方库，见三方库支持列表。

如果原始模型脚本中，调用了第三方依赖库，且三方库使用的是CPU，可以使用pip install命令安装相应的依赖库，然后按照CPU上的方式使用即可。

说明： 
如果您在太初AI加速卡上使用CPU相关的第三方库时，遇到CPU依赖问题，可以联系太初技术支持获取帮助。

处理TecoPyTorch不支持的算子及函数
如果原始模型中存在TecoPytorch当前不支持的算子（包括自定义的CUDA算子），TecoPyTorch会自动回落该算子到CPU进行计算；如果这些算子也不支持在CPU上运行，则需要参考SDAA C编程指南，重新开发算子。

说明： 
TecoPytorch当前支持的算子，请参考PyTorch算子类API支持说明。

以下PyTorch接口在TecoPytorch框架中没有对应的接口实现，请您在迁移前，对这些接口进行处理，否则迁移后的模型可能无法运行或者报错：

torch.backends.cudnn

torch.backends.cuda

torch.autograd.profiler.emit_nvtx

torch.cuda.nccl

torch.cuda.CUDAGraph

torch.UntypedStorage._release_ipc_counter_cuda

torch.UntypedStorage._share_cuda_

torch.UntypedStorage._new_shared_cuda

torch.TypedStorage._release_ipc_counter

torch.TypedStorage._share_cuda_

torch.TypedStorage._new_shared_cuda

卷积算子计算
针对卷积计算，太初目前仅支持float16数据类型。如果模型中存在卷积计算，且没有开启autocast混合精度训练，仍需要添加GradScaler相关代码，从而避免由于float16数据类型导致的精度下降问题。TecoPyTorch中添加GradScaler的示例代码如下：

scaler = torch.sdaa.amp.GradScaler()    # 定义GradScaler
epochs = 2  # 设置训练的循环次数

for epoch in range(epochs):
    for imgs, labels in train_dataloader:
        # 将数据和标签放置在device上并转换为channels_last格式
        imgs, labels = imgs.to(device).to(memory_format=torch.channels_last), labels.to(device)
        with torch.sdaa.amp.autocast():   # 开启AMP环境
            outputs = model(imgs)    # 前向计算
            loss = loss_func(outputs, labels)    # 损失函数计算

        optimizer.zero_grad()
        scaler.scale(loss).backward()    # loss缩放并反向转播
        scaler.step(optimizer)    # 参数更新
        scaler.update()    # 基于动态Loss Scale更新loss_scaling系数
