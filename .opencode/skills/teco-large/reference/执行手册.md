# 模型适配执行手册（Agent 实战版）

本手册是对 `SKILL.md`（赛事规则原文）的补充：把“怎么一步步做完”的操作流程、精确命令、
判断依据和踩坑经验固化下来。面向任意目标模型，按阶段执行即可。

> 术语：**modelzoo** = `tecovllm-modelzoo-{队名}`（模型侧）；**teco-ops** = `teco-ops-{队名}`（算子侧）。

```bash

```

版本自检：

```bash

```

**一致性要求**：`torch_sdaa` 与 SDAA Runtime 必须匹配（本环境经验值：`torch_sdaa 20260623.8.51`
配 `Runtime/TecoDNN/TecoBLAS/TCCL 3.2.0`、`SDPTI 1.7.0`）。若运行时报
`warning: driver api and driver versions are different`，且算子出现 `invalid argument` / TCCL 卡死，
说明运行时被升级过，需要回退：

- 3.2.0 RPM 源：`/workspace/SDAA_FT/env_file/`（sdaart/tccl/tecodnn/tecoblas/sdpti/sdaadriver…）
- 3.3.0 RPM 源：`/var/teco-repo/tecotoolkit/`
- 回退命令（示例）：
  ```bash
  cd /workspace/SDAA_FT/env_file && rpm -Uvh --oldpackage --nodeps --force \
    sdaart-3.2.0-1.lns23.loongarch64.rpm tccl-3.2.0-1.lns23.loongarch64.rpm \
    tecodnn-3.2.0-1.lns23.loongarch64.rpm tecoblas-3.2.0-1.lns23.loongarch64.rpm \
    sdpti-1.7.0-1.lns23.loongarch64.rpm sdaadriver-3.2.0-1.lns23.loongarch64.rpm
  ```
- **注意**：`vllm_sdaa._C.so` 依赖 `tecolmk 3.3.0` 的符号
  （`tecolmkFusedRecurrentGatedDeltaRuleV2`），所以 `tecolmk` 要保持在 3.3.0：
  ```bash
  rpm -Uvh --nodeps --force /var/teco-repo/tecotoolkit/tecolmk-3.3.0-1.lns23.loongarch64.rpm
  ```
- 磁盘打满会导致 RPM 装不上：先清理 `/tmp`、`~/.cache` 等。

SDAA 设备模型：单卡暴露 **4 个核组**（`torch.sdaa.device_count()==4`），TP=4 时要
`export SDAA_VISIBLE_DEVICES=0,1,2,3`；否则 worker 断言 `local_world_size <= visible_device_count` 失败。

## 阶段 1：模型分析（动手前必做）

1. **拿 config**：读 `<model_path>/config.json`
   - `architectures[0]`（注册时的 `model_arch` 必须完全一致）
   - `model_type` / 嵌套 `text_config.model_type`（transformers 是否认识 → 是否需要自定义 config）
   - 结构字段：`num_hidden_layers / hidden_size / num_attention_heads / num_key_value_heads /
     head_dim / global_head_dim / layer_types / sliding_window / rope_parameters /
     attention_k_eq_v / num_global_key_value_heads / tie_word_embeddings / dtype`
2. **拿权重命名与形状**（不用加载全量权重）：
   ```python
   import json, struct
   p = "<model_path>/model.safetensors"
   with open(p, "rb") as f:
       n = struct.unpack("<Q", f.read(8))[0]
       hdr = json.loads(f.read(n))
   keys = [k for k in hdr if k != "__metadata__"]
   # 看前缀（如 model.language_model.*）、q/k/v 形状、是否有 v_proj（k_eq_v）、layer_scalar、vision/audio
   ```
   这一步决定 `load_weights` 的映射规则。
3. **量化格式**：仅支持 FP16 / INT8；SDAA 运行一般用 `--dtype float16`。
4. **可运行性**：确认模型能被 transformers/vLLM 解析；解析失败就准备自定义 config（见阶段 3）。
5. **判断参考实现**（阶段 2）。

## 阶段 3：实现组网（modelzoo）

### 3.1 文件与注册
- 组网文件：`tecovllm_models/models/<name>.py`（如 `gemma4_dense.py`）
- 注册：`tecovllm_models/__init__.py` 的 `init()` 里 `ModelRegistry.register_model(model_arch=..., model_cls=...)`
- 自定义 config（当 `model_type` 不被 transformers 认识时）：
  `tecovllm_models/configs/<name>.py`，用 `AutoConfig.register(model_type, ConfigClass, exist_ok=True)`；
  嵌套子配置（`text_config`/`vision_config`/`audio_config`）转成 `PretrainedConfig` 实例，
  这样 `config.get_text_config()` 能返回文本配置。

### 3.2 必备接口
```python
class XxxForCausalLM(nn.Module):
    def embed_input_ids(self, input_ids) -> torch.Tensor: ...
    def forward(self, input_ids, positions, intermediate_tensors=None, inputs_embeds=None): ...
    def compute_logits(self, hidden_states): ...
    def load_weights(self, weights): ...   # 返回 set[str]；注意 packed/前缀/k_eq_v/多模态跳过
```
- `load_weights` 常见处理：剥离前缀（如 `language_model.`）；`q/k/v_proj → qkv_proj`、
  `gate/up_proj → gate_up_proj` 的 shard 加载；`k_eq_v` 层用 k_proj 复制成 v_proj；
  `named_buffers()` 也要纳入（如 `layer_scalar`）；跳过 vision/audio 权重。
- 嵌套路复用 `vllm.model_executor.models.utils.AutoWeightsLoader`（在子模块上实现 `load_weights`
  处理 packed mapping，外层 loader 会递归调用）。

### 3.3 层接入 tecovllm_models（强制使用 tecoops 三算子）
- Norm → `from tecovllm_models.layers.rms_norm import RMSNorm`（内部走 `tecoops.rms_norm`；
  无权重 norm 用 `has_weight=False`）
- RoPE → `tecovllm_models.layers.rotary_embedding`（`RotaryEmbedding` / `Gemma4RotaryEmbedding`）
- Attention → 用 vLLM `Attention(..., attn_backend=FlashAttentionBackend)`
  （`from tecovllm_models.layers.flash_attn import FlashAttentionBackend`），
  sliding 层通过 `per_layer_sliding_window=...` 传入。

> 不要用 vLLM 自带 `RMSNorm/get_rope/默认 attention backend`，否则未接入 tecoops 会被判违规。

### 3.4 通用骨架
见 `reference/model_skeleton.py`。

## 阶段 4：算子接入与 teco-ops 改动

详见 `reference/算子接入约束.md`。要点：
- FA kernel 只支持 **HND** KV 布局、**block_size=32**；必须有 sliding window 与 softmax scale 透传；
- `head_dim > 128` 时要缩小 Q tile（`BM`）避免 SPM(~256KB/SPE) 溢出；
- `rms_norm` 需要非空 weight（weight-less 传 ones）；只支持 fp16。

若目标模型需要新的 kernel 能力（如 sliding、不同 head_dim），在 teco-ops 改：
`teco/ual/kernel/<op>/*.scpp` + `teco/ual/args/*.h` + `teco/interface/ops/*.cpp` +
`teco/interface/include/tecoops.h` + `api/torch_ext.cpp`，然后重编译。

## 阶段 6：验证

1. **离线冒烟**（`LLM.generate`，见 `reference/离线推理.py`）
   - 脚本必须放在 `if __name__ == "__main__":` 里（vLLM 用 spawn）
   - `os.environ["SDAA_VISIBLE_DEVICES"]="0,1,2,3"`（否则 TP=4 起不来）
   - `dtype="float16"`, `tensor_parallel_size=4`, `enforce_eager=True`（先求稳）
2. **在线服务**（`run.sh`），用 chat 发一条，确认输出通顺
3. **精度**：`evalscope eval`（命令见 SKILL 第 4 节，必须与 CUDA 一致）
4. **性能**：`evalscope perf`（见 SKILL 第 5 节）

`max_model_len` 受单卡显存限制：12B(fp16)+TP4 实测 KV 约 3.8 万 token，`--max_model_len 32768`
可行；spec 示例的 262144 在单卡上不现实，`run.sh` 可按需调小（评测最长 16K 输入）。
