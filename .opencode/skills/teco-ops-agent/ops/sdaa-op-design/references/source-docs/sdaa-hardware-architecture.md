## 零、T1 芯片顶层架构（pic0）

T1 芯片包含 **4 个核组 (SPA, Signal Processing Array)**，每个核组独占一块 **HBM (16GB)**：

```plaintext
        ┌─────────┐         ┌─────────┐
  HBM ←→│  核组0   │←──┐  ┌→│  核组1   │↔ HBM
        │ (SPA)   │   │  │  │ (SPA)   │
        └────┬────┘   │  │  └────┬────┘
             │        │  │       │
   ┌────────┼────────┘  └───────┼────────┐
   │      中央互连网络               (粉色圆角矩形)     │
   │                                        │
   └────────┬──────────────┬────────────────┘
            │              │
       ┌────┴────┐   ┌────┴────┐
 HBM ←→│  核组3   │   │  核组2   │↔ HBM
       │ (SPA)   │   │ (SPA)   │
       └─────────┘   └─────────┘

                          ↔ 主机(Host, PCIe+DDR)
```

**当前 matmul 开发只需单核组执行**，以下内容聚焦单核组内部（32个SPE）。

### 1.3 坐标体系与DMA引擎绑定关系

> **⚠️ 重要: DMA引擎按列绑定，不是按行！每列4个SPE共享1个DMA引擎。**

```plaintext
        col0      col1      col2      col3      col4      col5      col6      col7
         ↑          ↑          ↑          ↑          ↑          ↑          ↑          ↑
       DMA0       DMA1       DMA2       DMA3       DMA4       DMA5       DMA6       DMA7
         │          │          │          │          │          │          │          │
    ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
row0│ SPE0 │ SPE1 │ SPE2 │ SPE3 │ SPE4 │ SPE5 │ SPE6 │ SPE7 │
    ├──────┼──────┼──────┼──────┼──────┼──────┼──────┼──────┤   ← 每列4个SPE共用1个DMA
row1│ SPE8 │ SPE9 │SPE10 │SPE11 │SPE12 │SPE13 │SPE14 │SPE15 │     引擎（优先级一致）
    ├──────┼──────┼──────┼──────┼──────┼──────┼──────┼──────┤
row2│SPE16 │SPE17 │SPE18 │SPE19 │SPE20 │SPE21 │SPE22 │SPE23 │
    ├──────┼──────┼──────┼──────┼──────┼──────┼──────┼──────┤
row3│SPE24 │SPE25 │SPE26 │SPE27 │SPE28 │SPE29 │SPE30 │SPE31 │
    └──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘
```

**关键规则**:

*   TID ∈ \[0, 31\], `row = tid // 8`, `col = tid % 8`
    
*   NUM\_COLS = 8 (硬编码常量)
    
*   **DMA引擎归属**: `dma_engine_id = col` (即 tid % 8)
    
    *   col0 的 SPE0/SPE8/SPE16/SPE24 → 共享 **DMA0**
        
    *   col1 的 SPE1/SPE9/SPE17/SPE25 → 共享 **DMA1**
        
    *   ...以此类推
        
*   **行没有专属DMA引擎** — 行广播时需要借助对角线方案利用多列的DMA
    
*   物理到逻辑映射: `logical_block_id = loop_count * 32 + physics_block_id`

## 二、存储层级 (Memory Hierarchy)

### 2.1 HBM2 (全局内存)

| 属性 | 值 | 说明 |
| --- | --- | --- |
| Vendor | Samsung | — |
| 容量 | **16 GB** | 每个核组(SPA)独占 |
| 物理通道 | 8 × 128 bit | 独立运作 |
| 伪通道 | 16 (8phys × 2pseudo) | HBM2特性，绕过tFAW限制 |
| Bank | 32 (8 BankGroup × 4 Bank) | BG间并行，BG内有少量切换开销 |
| Row Size | 1 KB / PC | 行缓冲容量 |
| 最小粒度 | **32 B** | 地址需32B对齐 |
| PPU包大小 | **128 B** | 必须地址128B对齐！PPU不合并请求 |
| MC通道数 | **16** (Channel0~Channel16) | pic15显示 |
| 理论带宽 | **409.6 GB/s** | 1024bit/8 × 3.2GHz |
| 有效带宽 | **~328 GB/s** (80%) 或 **~130.8 GB/s** (实测) | pic1标注 |

> **⚠️ 重要更正**: pic1 标注 HBM 实测聚合带宽为 **130.8 GB/s**（全核组视角），远低于理论值。单SPE的DMA\_GET=256GB/s和PUT=331GB/s是引擎侧理论峰值，受MC/HBM瓶颈约束实际更低。

**HBM 地址映射规则**:

```plaintext
PA[5:6]   → CA[1:2]   (列地址低位，突发内偏移)
PA[12:14] → CA[3:5]   (列地址高位，大数据块选择)
PA[7:9]   → CH[0:2]   (通道号, 3位→8通道)
PA[10]    → BA[4]     (伪通道标识)
PA[11]    → BA[2]     (BG组内标识)
PA[15:16] → BA[0:1]   (Bank ID)
PA[17]    → BA[3]     (BG组间标识)
PA[18]    → SID BG    (堆栈标识)
PA[19:33] → RA[0:14]  (行地址, 15位)
```

**HBM 访存可视化** (pic7~10):

*   低7位 = 同一通道内偏移
    
*   后4位 = 通道号 → 共16个通道，每通道128B
    
*   每通道内部按16个Bank并行展开
    
*   **低19位为同一行** → 控制32核同时访问不超过512KB（每核≤16KB）
    

**访存优化原则**:

1.  使用**周期划分**(cyclic)而非块划分(block)，避免跨行访问
    
    *   块划分(pic11): 各SPE连续但核组视角不连续 → 通道未打满
        
    *   跨步周期划分(pic12): 单核不连续但核组视角连续 → 通道打满 ✅
        
2.  每SPE访问数据量控制在 **8-16 KB**（32核总计≤512KB避免跨行）
    
3.  连续访问 ≥ 1KB 保证DMA通道利用
    
4.  **以整个核组视角看待HBM地址连续性**
    

**访问成本排序**: Channel切换 < Column切换 < Bank切换 < **Row切换**(最贵!)

### 2.2 LDM (Local Data Memory) ⚠️ 重大更正

> 来源: **pic33 (Tecorigin太初元睿官方图)** + teco-T1.md文字

```plaintext
┌─────────────────────┐     ┌─────────────────────┐
│      DMA            │     │      DMA            │
│      RMA            │512b │      RMA            │
│      LD/ST          │←──→│  128KB              │ ← 高128KB
│      ACE            │     ├─────────────────────┤
│                     │     │  128KB              │ ← 低128KB
│                     │     │                     │
└─────────────────────┘     └─────────────────────┘

        总共256KB                    伪双端口
        高低128KB各有独立端口         端口共享(非真正双端口)
```

| 属性 | 值 | 说明 | 来源 |
| --- | --- | --- | --- |
| **总容量** | **256 KB** | 伪双端口架构 | pic33 ⚠️ |
| **高半区** | **128 KB** | 独立端口号 | pic33 |
| **低半区** | **128 KB** | 独立端口号 | pic33 |
| malloc空间 | ~235 KB | 用户可用(扣除编译器内部) | 文字描述 |
| 函数栈 | **16 KB** | 自动分配释放 | 文字描述 |
| `__local__` 变量 | **2656 B** | 不支持init, 只能全局变量 | 文字描述 |
| 端口位宽 | **512 bit** | 四路共享(DMA/RMA/LDST/ACE) | pic33 |
| Bank结构 | **两个独立Bank** | Bank0 + Bank1, 各128KB | pic28 |
| 访问模式 | **互不影响** (伪双端口) | 两Bank可同时被不同master访问 | pic28 |
| SIMD读LDM带宽极限 | **160 GB/s** | 512bit/8 × 2.5GHz = 处理器指令速度极限 | pic28 |

> **关键洞察 (pic28)**:

*   LDM分两个Bank (Bank0/Bank1), 对应前后各128KB
    
*   **如何把DMA、RMA、ACE和SIMD的流量错开到两个不同Bank是重要优化点**
    
*   LDM位宽512bit > Mesh网络256bit → 同时收发时存在隐式转换瓶颈
    
*   ACE工作在半频1.25Ghz下，两拍数据流动一次产生一行新结果
    
*   **性能波动来源**: 芯片有两个时钟树，不同时钟树下性能可能不同（源于数据包仲裁），复位和降频可能导致ACE时间波动。此波动基本不影响业务场景。
    
*   **精度截断问题**: ACE内部精度fp32（可能不支持非规格化数），每次加载后把结果数截断为fp32；按fp32写回时写回fp32结果；按fp16写回时会**截断成不支持非规格化数的fp16**（此必然有很大精度损失，可能是上一代芯片精度不好的主要问题，因此可考虑手动载入bf16方案）

| 属性 | 值 | 说明 |
| --- | --- | --- |
| 缓冲区数量 | **2个** (buffer 0 / buffer 1) | 双缓冲，见pic26 |

**ACE完整数据流** (pic26 + pic27):

```plaintext
西向(A矩阵) ──→ ┌──────────────────────┐
                 │  整形部件            │  西向数据列优先存储 (128×32 fp16)
北向(B矩阵) ──→ │                      │  北向数据缓冲0,1优先存储 (32×32 fp16)
                 │  北向数据缓冲0        │
                 │  北向数据缓冲1        │
                 ├──────────────────────┤
                 │  北端数据加载配器      │  → 统一送入MXMU
                 ├──────────────────────┤
                 │  矩阵乘法单元 MXMU    │  mul-add脉动阵列
                 │  [mul+add]→[mul+add]→... │
                 │  矩阵算法单元阵列      │
                 │  [mul+add]→[mul+add]→... │
                 ├──────────────────────┤
                 │  (+)(+)  (+)(+)      │  累加器缓冲0 / 1
                 │  累加器缓冲0  累加器缓冲1│  双缓冲!
                 └──────────┬───────────┘
                            ↓ writeback
                        LDM存储
```

**ACE模块组成 (pic27)**:

*   **SAC (加速控制器)**: 控制整个ACE流水线
    
*   **MXMU (Matrix Multiply Unit)**: 矩阵乘法单元，执行mul-add脉动阵列
    
*   **ACMB (Accumulator Buffer)**: 累加器缓冲，双缓冲设计
    
*   **SAA\_IO**: IO访问控制，连接LDM

### 3.3 计算行为

**关键特性**: 调用 `rt_ace_load_west` 时**自动进行乘加计算**，无需单独调用计算指令！

K循环流程:

1.  配置ACE (`rt_ace_config`)
    
2.  循环 K 次 (每次ace\_k=32):
    
    *   `rt_ace_north_load` — 加载B矩阵数据到North口
        
    *   `rt_ace_load_west` — 加载A矩阵数据到West口 + **触发乘加累加**
        
3.  `rt_ace_writeback(memb)` — 将空闲累加器buffer结果写回LDM
    
4.  `rt_ace_barrier` — ACE同步
    

例如 K=384 = 12 × ace\_k(32)，循环12次后一起写出ACE结果，性能较优。

### 3.5 ACE 指令集

来自 ace\_macro.h 的内联汇编指令:

```asm
; 配置kernel类型
ace %reg, 0x11          ; Comptype(4bit配置参数)

; North口加载B矩阵
ace %reg, 0x12          ; Waddr(20bit), Loadstride(32bit)

; West口加载A矩阵 + 触发乘加
ace %reg, 0x13          ; Xaddr(20bit), Accumaddr(7bit),
                        ; Accumflag(1bit), Xsize(8bit),
                        ; Loadstride(8bit), Lastflag(1bit), Northflag(1bit)

; 结果写回LDM (memb=memory barrier)
memb
ace %reg, 0x14          ; Yaddr(20bit), Ysize(8bit),
                        ; Yrply(20bit), Precisionflag(1bit)

; ACE同步barrier
ace $32, 0x18

; 清除状态寄存器
wcsr $31, 0x34          ; north_clear
wcsr $31, 0x35          ; west_clear
```

**West Load 标志位说明**:

*   `Accumflag`: 是否切换累加器缓冲区 (0/1)
    
*   `Lastflag`: 是否为最后一次West加载
    
*   `Northflag`: 是否同时触发North加载
    
*   `Yrply`(Writeback): 广播reply数量控制
    
*   `Precisionflag`: fp16/fp32输出精度

## 四、Mesh 网络 (核间互连)

### 4.1 网络结构

组件: **DMA引擎** + **从核(SPE/LDM)** + **路由** + **双工连线**

| 参数 | 值 |
| --- | --- |
| 网络位宽 | 256 bit |
| 主频 | 2.5 GHz (与SPE相同) |
| 极限带宽 | **80 GB/s** (双工) = 2.5G × 256/8 |
| 可用带宽 | **64 GB/s** (双工) = 80 × 4/5 (包头:包身=1:4) |
| 拓扑 | 2D Mesh + 路由转发 |

### 4.2 方向性与并发

**一级连接是全双工**: 每个节点可以同时上网和下网。

*   **DMA PUT(上网) + RMA接收(下网)**: 不冲突 ✅
    
*   **DMA PUT(上网) + RMA发送(上网)**: 冲突 ❌ (同一方向)
    
*   **DMA GET(下网) + RMA发送(上网)**: 不冲突 ✅ (反向)
    

**LDM→网线瓶颈**: LDM位宽512bit, Mesh位宽256bit, 同时收发时存在隐式瓶颈。

### 4.3 传输示例

SPE0 → SPE4 传输路径:

```plaintext
SPE0.LDM → [网线段1] → Router → [向右转发] → ... → Router → [下网] → SPE4.LDM
```

如果SPE0同时DMA PUT: 在"网线段1"处发生上网方向冲突。

## 五、DMA 引擎

### 5.1 架构

| 属性 | 值 |
| --- | --- |
| 总数量 | **8 个** |
| 绑定方式 | 每列1个 (col0→DMA0, ..., col7→DMA7) |
| 共享方式 | 同列4个SPE共享1个DMA引擎 |
| 连接方式 | 4条独立线连接4个SPE (优先级一致) |
| 返回通路 | DMA返回与RMA**共用线路** |

### 5.2 能力约束

| 约束 | 值 | 影响 |
| --- | --- | --- |
| 单引擎最大HBM通道 | **2** | 4~5引擎可打满HBM |
| 数据包大小 | **128 B** | 地址必须128B对齐 |
| PPU合并 | **不支持** | 4B请求=128B请求效率 |
| 队列深度 | **11** | 第12次请求延迟暴增! |
| 队列类型 | **读写共用** | 读+写总数≤11 |
| MC并行Channel | **16** | 最佳128B×16=2KB覆盖 |
| 最优单次访问 | **4 KB/SPE** | 双缓冲带宽最高 (pic17明确标注) |

### 5.3 DMA跨步优化详细方案 (来自pic16~17)

**奇偶交错DMA引擎编号** (避免交叉开关冲突, pic16):

```plaintext
原始:    DMA0 DMA1 DMA2 DMA3 DMA4 DMA5 DMA6 DMA7
                    ↓ 奇偶交错
重排后:   (0)  (2)  (4)  (6)  (1)  (3)  (5)  (7)
```

两种方案对比:

*   方案1: `0→1, 2→3, 4→5, 6→7` (顺序) → 可能占用冲突
    
*   方案2: `0→3, 2→1, 4→7, 6→5` (交叉) → 避免占用 ✅ 推荐
    

**周期划分 + 跨步传输** (pic17):

*   每个从核搬运数据量 = **4KB** → 每小块(如tid 0~7)搬运32KB
    
*   每个 loop 搬运数据量 = 128KB
    
*   跨步参数: bsize=**128B**, stride=**7×128B**\=896B
    
*   tid顺序对应DMA引擎通道号: `{0,2,4,6,1,3,5,7}`
    
*   目的: 让不同tid的DMA请求命中不同的HBM通道和Bank，避免bank冲突
    
*   余数段处理: <128KB的数据由tid 0~31一起处理

### 6.3 优化建议

1.  **优先使用 RMA PUT** (某些场景下GET更慢，如ring)
    
2.  **列广播天然高效** (8DMA引擎全利用)
    
3.  **行广播必须用对角线/双对角线优化** (否则只用1个DMA引擎)
    
4.  **避免同时 DMA\_GET + RMA列广播** (返回通道冲突导致拥塞)
    
5.  大数据量(≥128KB)场景: **点对点 > 广播**

## 七、单SPE内部架构 (来自 pic2 — 完整分析版)

> pic2 是"从核0"的完整内部框图，是理解SPE微架构最关键的图。

```plaintext
                    ┌──────────────┐
                    │  L1 ICache   │  ← 指令缓存
                    └──────┬───────┘
                           │ 取指
                    ┌──────▼───────┐         ┌──────────────────────┐
                    │    IBOX      │◄═══════►│  脉动阵列 ACE         │
                    │ (指令发射单元) │  控制    │  32×32, **半频1.25G**│
                    └──────┬───────┘  双向     └────────▲────────────┘
                           │               指令通路        │ 数据(ACE→MBOX直连)
                    ┌──────▼───────┐                  │
                    │    EBOX      │                  │
                    │ (向量执行单元) │◄════════════════┘ 数据(EBOX←ACE)
                    └──────┬───────┘
                           │              ┌────────────────┐
                    ┌──────▼───────┐       │                │
                    │    MBOX       │◄──────┘                │
                    │ (存储访问单元)  │  数据                 │
                    └──┬────────┬───┘                        │
                       │        │                            │
                   port0│      port1│                        │
           ┌───────────┘        └───────────┐                │
                       ▼                     ▼               │
                 ┌─────────────────────────────┐            │
                 │            LDM              │ ◄═══════════┘
                 │  分半区(Bank0+Bank1), 两个port│
                 │       256KB total             │
                 └─────────────────────────────┘

          ┌────────────┐  ┌────────────┐  ┌────────────┐
          │    SRU     │  │    TBOX    │  │    SBOX    │
          │  标量寄存器 │  │  转移/跳转  │  │  存储管理   │
          │  单元(r0~31)│  │  控制单元   │  │  辅助单元   │
          └────────────┘  └────────────┘  └────────────┘
```

### 7.1 五大核心模块详细说明

| 模块 | 全称 | 功能 | 频率 |
| --- | --- | --- | --- |
| **IBOX** | Instruction Box | 指令发射、译码，**2译码-2发射**超标量 | 2.5 GHz |
| **EBOX** | Execution Box | 向量/SIMD执行，**512位宽**，p0+p1双发射 | 2.5 GHz |
| **MBOX** | Memory Box | 存储访问控制，连接LDM的两个port | 2.5 GHz |
| **ACE** | 加速计算引擎(Cube Unit) | 32×32脉动阵列，矩阵乘法专用 | **1.25 GHz (半频)** |
| **LDM** | Local Data Memory | 片上数据存储，256KB伪双端口 | — |

### 7.2 辅助单元

| 模块 | 全称 | 功能 | 关联资源 |
| --- | --- | --- | --- |
| **SRU** | Scalar Register Unit | 标量运算，管理 r0~r31 (64bit) | 标量寄存器文件 |
| **TBOX** | Transfer Box | 转移/跳转控制，分支预测 | 程序计数器/状态 |
| **SBOX** | Storage Box | 存储管理辅助（地址变换等） | 地址空间管理 |

### 7.3 数据通路关系（pic2 箭头含义）

```plaintext
                    ════════════════════════════════════
                    数据通路 (粗箭头/蓝色)
                    ════════════════════════════════════

    L1 ICache ──取指──→ IBOX ──指令发射──→ ACE (控制)
                                    ↕ (双向, 控制信号)

    LDM ←port0/port1─→ MBOX ──数据──→ EBOX (SIMD读写LDM)

                              ↑
    MBOX ─────────────────────┘ (ACE也可直接通过MBOX访问LDM!)
    
    ACE ←──数据── EBOX? (图中显示ACE↔MBOX有直接通路, ACE↔EBOX也有通路)

                    ······································
                    控制通路 (细箭头)
                    ······································

    IBOX ←──控制──→ ACE (IBOX负责向ACE下发load_west/writeback等指令)
```
> **关键洞察**: 从pic2的连线来看:

1.  **ACE ↔ MBOX 有独立数据通路** — ACE不经过EBOX就能读写LDM（West/North加载、Writeback写回）
    
2.  **ACE ↔ EBOX 有数据交互** — 可能用于结果从ACE传回EBOX做后续SIMD处理
    
3.  **IBOX → ACE 是纯控制通路** — IBOX作为指令发射器统一调度ACE和EBOX
    
4.  **这意味着 ACE计算 和 SIMD(EBOX)计算 可以并行执行**, 但两者访问LDM时可能通过MBOX竞争port资源

## 八、EBOX / SIMD (向量单元)

| 属性 | 值 |
| --- | --- |
| 执行单元 | EBOX |
| 流水线 | 2条 (p0=访存/load-store, p1=计算/alu) |
| 向量寄存器 | r32~r63, 共32 × 512 bit |
| 标量寄存器 | r0~r31, 共32 × 64 bit |
| 每周期处理 | 16 FP32 / 16 FP16 / 16 INT / 32 SHORT |
| 峰值带宽 | **160 GB/s** (512bit/8 × 2.5G) |

**指令双发射示例** (pic31~pic32):

```c
// pic32: 优化前 - load和计算有数据依赖，无法充分流水化
simd_load(a0, ...); simd_load(a1, ...);  // 8个load
simd_load(b0, ...); simd_load(b1, ...);  // 4个load
a0 = a0 * b0;  a1 = a1 * b1;              // 等待所有load完成!
// → 实测248cycle, 计算指令256条+循环开销 > 256cycle

// pic33: 优化后 - 将load和计算交错，利用双发射
simd_load(a0, ...);                       // p0: load a0
simd_load(a1, ...);
a0 = a0 * b0;                             // p1: compute (与后续load并行!)
simd_load(a4, ...);                       // p0: load a4
a1 = a1 * b1;                             // p1: compute
simd_load(a5, ...);                       // p0: load a5
a3 = a3 * b3;                             // p1: compute
// → 平均每次执行接近1 cycle!
```

## 九、执行模型与指令流

### 9.1 指令特性

*   **所有指令异步发射**: 无依赖时后一条无需等前一条完成
    
*   **5级流水线** (pic30): **IF → ID → EX → MEM → WB**
    
    *   IF: 取指 | ID: 译码 | EX: 执行 | MEM: 存储访问 | WB: 写回
        
*   **双发射(超标量)**: load/store(p0) + compute(p1) 可同cycle发出（见第八章示例）
    
*   平均指令latency: 流水线满载时接近 **1 cycle/instr**
    

```plaintext
  TIME →
  ┌────┬────┬────┬────┬────┬────┐
  │ IF │ ID │ EX │MEM │ WB │    │  指令1
  ├────┼────┼────┼────┼────┼────┤
      │ IF │ ID │ EX │MEM │ WB │    │  指令2 (cycle2发射)
      ├────┼────┼────┼────┼────┤
          │ IF │ ID │ EX │MEM │ WB │  指令3 (cycle3发射)
          └────┴────┴────┴────┴────┘
```

### 9.2 同步原语

```c
sync_threads();                              // 所有32个SPE同步
sync_threads(thread_group, thread_group_size); // 指定SPE子组同步
```

### 9.3 内存模型

| 空间 | 接口 | 说明 |
| --- | --- | --- |
| Host ↔ Global(HBM) | `sdaaMemcpy` | 主机-设备拷贝, PCIe 7GB/s + DDR 3GB/s |
| 设备内部 | `memcpy` | 同一core内部 |
| HBM ↔ LDM(SPM) | `dma` | 跨步/连续/同步/异步, 支持转置, 8GB/s@300Cycle |
| Inter-core LDM↔LDM | `rma` | 同步/异步, 基于Mesh网络 |
| Broadcast | 行/列广播 | 单点/掩码自定义组, 阻塞/非阻塞 |

### 9.4 DMA/RMA/ACE 三者并发关系 (来自pic1/pic28)

| 操作 | 使用资源 | 可并发条件 |
| --- | --- | --- |
| DMA GET | DMA引擎 + Mesh下网方向 | ✅ 与RMA PUT(上网)不冲突 |
| DMA PUT | DMA引擎 + Mesh上网方向 | ❌ 与RMA PUT(上网)**冲突!** |
| RMA PUT | LDM→Mesh上网 | ✅ 与DMA GET(下网)不冲突 |
| RMA GET | Mesh下网→LDM | ⚠️ 与DMA GET返回通道**共享**, 可能拥塞 |
| ACE计算 | West/North口 + ACMB | ✅ 与SIMD(EBOX)不同硬件单元 |
| SIMD操作 | EBOX + LDM Bank访问 | ⚠️ 与ACE/MBA共享LDM端口，需错开Bank |

> **关键并发规则**: DMA\_GET数据在下网，RMA传输的数据在上网，**全双工不冲突**。但DMA PUT(上网)+ RMA发送(上网)=同向冲突。

## 十一、已知性能优化经验总结

### GEMM 场景 (基于ACE.xlsx + pic26~28)

1.  **M\_TILE = 96**: TFLOPS较高(67.1)且LDM装得下
    
2.  **K循环多次累加后一起写出ACE**: 比每次写出快（减少写回次数）
    
3.  **SplitK决策**: 取决于M/N/K和LDM容量 (见GEMMCostModel)
    
4.  **双缓冲**: ACE累加器天然双缓冲(buffer 0/1) + LDM中A/B矩阵ping-pong
    
5.  **精度选择**: ACE内部fp32累加，**写回时用fp32避免截断损失**(fp16写回会丢失非规格化数)
    
6.  **West加载频率优化**: West=128行时每个West需重新加载North，等效15GB/s带宽；需至少11-12次连续West加载才能占右侧稳定波动
    

### DMA 场景 (基于pic13~17)

1.  单SPE每次搬运 **4KB** 最优（pic17明确标注）
    
2.  同时发起DMA ≤ **11条** (读写共享队列, 第12条延迟暴增!)
    
3.  地址必须 **128B 对齐** (PPU不合并请求, 4B=128B效率相同)
    
4.  使用**周期划分**(cyclic)让核组视角地址连续（pic12对比pic11）
    
5.  奇偶交错DMA引擎编号: `(0,2,4,6,1,3,5,7)` 避免交叉开关冲突(pic16)
    
6.  跨步传输: bsize=**128B**, stride=**7×128B**, tid映射通道号`{0,2,4,6,1,3,5,7}`(pic17)
    

### RMA/广播 场景 (基于pic18~25)

1.  优先使用 **RMA PUT** 非 GET (某些场景GET更慢, 如ring)
    
2.  **列广播**: 普通列广播即可(8个DMA引擎全利用), 大数据量用**跨步列广播**更优
    
    *   跨步列广播 @128K每列 = **278 GB/s总量**
        
    *   普通列广播 @128K每列 = **182 GB/s总量**
        
3.  **行广播必须用对角线/双对角线优化**:
    
    *   普通行广播仅42 GB/s(只用了1个DMA引擎!)
        
    *   双对角线行广播 @128K每行 = **188 GB/s总量**
        
4.  避免 DMA\_GET + RMA广播同时进行 (返回通道冲突导致拥塞)
    
5.  大数据量场景: **点对点PUT > 广播**
    

### LDM Bank 优化 (来自pic28/pic33)

1.  LDM分Bank0/Bank1各128KB, 各有独立端口
    
2.  **将DMA、RMA、ACE和SIMD的流量错开到两个不同Bank是重要优化点**
    
3.  SIMD读LDM带宽极限160GB/s (512bit×2.5G), 但受限于LDM端口共享
