# SDAA T1 访存与流水线优化方法论

> 适用范围：SDAA T1 平台算子的访存时序、DMA/RMA 通道利用、LDM Bank 调度、流水线掩盖。
> 定位：本文是**分核决策之后**的访存/时序优化层，与 `分核.md`（分核切法与通信形态）互补。
> 分核回答"32 核怎么分工"；本文回答"搬的时候怎么不堵、怎么让计算盖住访存"。
> 配套：硬件知识库 `sdaa-hardware-architecture.md`，指令代价 `指令拍数和流水线派发.md`。

---

## 一、HBM 访存优化

- 地址 **128B 对齐**：PPU 不合并请求，4B 请求与 128B 请求效率相同。
- 单次搬运 **1~16 KB**，最优 ~4 KB/SPE（双缓冲带宽最高）。
- 同时挂起 DMA **≤ 11**（读写共用队列，第 12 条延迟暴增）。
- 访存成本排序：Channel 切换 < Column 切换 < Bank 切换 < **Row 切换（最贵）**。
- 周期划分（cyclic）让核组视角地址连续、打满 16 通道（此条同时是分核切法，见分核.md 6.1）。

## 二、DMA 引擎利用

- 8 个 DMA 引擎**按列绑定**，每列 4 SPE 共享 1 个；loader 应散布到不同列。
- 非连续张量用跨步传输，`bsize ≥ 128B`。
- 奇偶交错 DMA 引擎编号 `{0,2,4,6,1,3,5,7}` 避免交叉开关冲突。
- 奇偶交叉配对：`0→3, 2→1, 4→7, 6→5`（交叉而非顺序），避免占用冲突。

## 三、RMA 通道与时序冲突（重点）

Mesh 全双工，分上网/下网两个方向。冲突判定看**"谁在收、谁在发、是否同向"**：

| 组合 | 方向 | 是否冲突 | 说明 |
| --- | --- | --- | --- |
| DMA GET + RMA PUT(发送) | 下行 / 上行 | ✅ 不冲突 | 反向，全双工 |
| DMA PUT + RMA PUT(发送) | 上行 / 上行 | ❌ 冲突 | 同向争用上网通道 |
| DMA GET + RMA 接收 | 下行 / 下行 | ⚠️ 可能拥塞 | 共享返回通路（见下） |
| DMA PUT + RMA 接收 | 上行 / 下行 | ✅ 不冲突 | 反向 |

### 3.1 "DMA GET + RMA 接收"的精确含义

这是 `sdaa-hardware-architecture.md` 中"避免 DMA_GET + RMA列广播（返回通道冲突）"的精确化。关键在**接收侧**：

- DMA GET：数据从 HBM **下行**进入本核 LDM。
- RMA 广播/环传的**接收端**：数据沿 **下行**进入本核 LDM。
- 两条下行流量共享 DMA 返回通路（硬件知识库："DMA 返回与 RMA 共用线路"）→ 同时进行可能拥塞。

**风险大小取决于接收侧 fan-in**：

| RMA 形态 | 接收侧流量 | 与 DMA_GET 重叠风险 |
| --- | --- | --- |
| **列广播** `col_ibcast` | 多对一下行汇聚（重） | 高 ❌ |
| **点对点环传** `rma_iput` | 每核只收 1 块（有界） | 低，可重叠 ✅ |
| **点对点 PUT** 单发 | 单源下行 | 低 |

### 3.2 规避手段

1. 需要重叠时，**优先点对点环传**而非列广播（接收 fan-in 轻）。
2. 用 **ACE/SIMD 计算掩盖**重叠期：先发起非阻塞 DMA_GET 和 RMA，紧接计算，wait 放在计算之后。
3. 实在要用广播：**错峰**——DMA_GET 与广播分属不同时间窗，避免真正同时。
4. 大数据量（≥128KB）单点对点 PUT 优于广播。

> 注：源文档对"DMA GET + RMA PUT 发送"给出的是 ✅（反向不冲突），但对"DMA GET + RMA 列广播接收"给出 ⚠️（可能拥塞）。两者不矛盾：前者看发送端，后者看接收端。读源文档时勿混。

## 四、LDM Bank 错开

- LDM 256KB 分 Bank0/Bank1 各 128KB，伪双端口，各有独立端口。
- 把 DMA 写入、RMA 收发、ACE 读写、SIMD 访问**分配到不同 Bank**，避免端口竞争。
- 这是 LDM "伪双端口"的关键利用点；四路流量（DMA/RMA/LDST/ACE）共享 512bit 端口，错开 Bank 才能并发。

## 五、流水线掩盖

- **双缓冲**：预取下一块 ‖ 计算当前块（DMA 被 ACE/SIMD 掩盖）。
- **ACE 写回 ‖ 下一段 ACE 计算**：累加器天然双 buffer（buffer 0/1）。
- **双发射**：load(P1) 与 compute(P0) 交错，平均接近 1 cycle/instr。
- 判据：`T_dma < 0.8·T_ace` 时启用双缓冲，稳态目标 `T_iter = T_ace`（DMA 完全被掩盖）。
- 重复加载可接受：LDM 双缓冲会覆写导致 A/B 重复 load，但只要 ACE 算力能掩盖 DMA，重复多少次都无所谓——重点是确保 `T_dma ≪ T_ace`，而非消除重复。

## 六、ACE 效率

- 优先把 K 做大：K=32→12.2T，K=384→67.1T（峰值 89%），K≥576 饱和 ~75T。
- 多次 K 段累加后一起 writeback，减少写回次数。
- 写回用 fp32 避免精度截断（fp16 写回会丢非规格化数）。
- West 连续加载 ≥11~12 次才进入稳定波动区。

## 七、常见访存/时序陷阱

1. **DMA PUT + RMA PUT 同时**：同向（上网）冲突。→ GET+PUT 反向搭配。
2. **忽略 LDM Bank 竞争**：DMA/ACE/SIMD 全挤一个 Bank。→ 显式错开到 Bank0/Bank1。
3. **DMA_GET + RMA 列广播接收同时**：返回通路拥塞。→ 改点对点环传或错峰（见 3.2）。
4. **DMA 队列打爆**：同时挂起 >11 条。→ 控制并发 DMA 数，用 reply 计数管理。
5. **地址未 128B 对齐**：PPU 不合并，小请求低效。→ 对齐访问，不足 128B 用 `rt_unaligned_*` 接口。
6. **同步/访存混在热循环**：MEMB、SYNC 在热点路径引入不定延迟。→ 结合 cycle 计数确认是否真热点，能移出循环就移出。
