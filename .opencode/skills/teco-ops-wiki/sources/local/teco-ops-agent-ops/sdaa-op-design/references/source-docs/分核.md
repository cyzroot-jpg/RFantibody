## 〇、什么是"分核"

SDAA T1 的一个**核组（SPA）**由 **32 个从核（SPE）**构成，呈 `4 行 × 8 列` 二维网格。算子每次启动以"一个 SPA = 32 个 SPE"为执行单位（主机侧 `<<<1>>>` 启动），算子的**并行性必须由开发者在这 32 个 SPE 之间显式划分**。

"分核"即回答四个问题：

1. **分哪个维度**——把张量的哪个轴切给 32 个 SPE？
2. **怎么复用数据**——相邻 SPE 共享的数据沿行/列广播，还是各自独立搬运？
3. **怎么均衡负载**——每个 SPE 的工作量是否相等？余数如何分配？
4. **怎么同步通信**——何时行同步、列同步、全局同步，何时需要核间归约？

本文档把这四个问题拆成**硬件约束 → 决策框架 → 五种分核模式 → 通用设计流程 → 性能优化**，逐层给出方法论。

> 多核组（4 个 SPA）协同属于"核组级"分核，由更高层调度，本文聚焦**单核组内 32 SPE 分核**，这也是绝大多数算子实际执行的层次。

## 一、硬件特性：分核的物理公理

分核不是自由选择，而是**硬件拓扑 × 数据依赖**的唯一（或有限）匹配。以下是不可变公理。

### 1.1 核组与 SPE 拓扑

```
SPA = 4 行(ROW) × 8 列(COL) = 32 SPE
tid ∈ [0,31],  row = tid // 8,  col = tid % 8
每个 SPE：LDM(256KB) + ACE(矩阵引擎) + EBOX(SIMD) + DMA接口
```

- 行方向（同一 row，col 0~7）：8 个 SPE 互连，**适合传播"只有 M 不同的数据"**。
- 列方向（同一 col，row 0~3）：4 个 SPE 互连，**适合传播"只有 N 不同的数据"**。
- 物理链路是全双工 2D Mesh，方向性决定广播代价不对称（见 1.5）。

### 1.2 LDM（片上私有存储，分核的容量上限）

| 属性 | 值 | 分核含义 |
| --- | --- | --- |
| 容量 | 256 KB（用户可用 ~235 KB） | 一个 tile 的数据必须装得下，**决定分块上限** |
| 结构 | 双 Bank（Bank0/Bank1 各 128 KB），伪双端口 | DMA/RMA/ACE/SIMD 流量应**错开到两个 Bank**避免端口竞争 |
| 位宽 | 512 bit | SIMD 读 LDM 极限 160 GB/s |
| 栈 | 16 KB 自动 | 分核时留出栈空间 |

**LDM 预算方程是分核可行性的硬判据，但方程形式取决于分核策略**。

通用推导规则：

```
LDM_used = Σ(每个 buffer 大小 × 份数) + 栈(16KB) ≤ 256KB (可用 ~235KB)

其中：
  份数 = 2  → 该 buffer 用了双缓冲（ping-pong）
  份数 = 1  → 单缓冲（不需要或被 ACE/DMA 掩盖）
  份数 = split_num → 空间 Split-K 的部分和，每 K 段一份

buffer 清单取决于策略：
  - 有矩阵乘 → A_tile, B_tile, C_tile（三块）
  - 有广播 → A/B 由 loader 取，其余核不占 LDM
  - 有环传 → 加 B_remote（接收对端数据）
  - 有归约 → 加 partial buffer（Split-K）或 reduce buffer（模式D）
  - 逐元素 → 只有输入/输出行 buffer（无 A/B/C 之分）
  - 权重共享（Conv）→ weight 是共享 buffer，只算一份
```

**按此规则推导常见策略的方程**：

| 策略 | 方程 | 推导 |
|------|------|------|
| 4×8 广播 GEMM（双缓冲） | `2·\|A\| + 2·\|B\| + \|C\| ≤ 235KB` | A/B ping-pong(×2)，C 单缓冲(×1) |
| 4×8 广播 GEMM（无重叠） | `\|A\| + \|B\| + \|C\| ≤ 235KB` | T_dma ≥ 0.8·T_ace，全单缓冲(×1) |
| 1D 平坦（M≤32） | `\|A_full\| + \|B_tile\| + \|C_tile\| ≤ 235KB` | A 全量单份(×1)，B/C 单缓冲(×1) |
| 32×1 独立 DMA | `\|A_tile\| + \|B_full\| + \|C_tile\| ≤ 235KB` | B 全量单份(×1)，A/C 单缓冲(×1) |
| Split-K | `策略基础方程 + (split_num-1)·\|C_partial\| ≤ 235KB` | 在基础策略上叠加，每多一段 K 多一份 C_partial |
| RMA Ring | `\|A_full\| + \|B_ring\| + \|B_remote\| + \|C\| ≤ 235KB` | 多一个 remote buffer |
| 模式A（逐元素） | `2·\|row_tile\| + \|weight\| ≤ 235KB` | 输入行双缓冲 + 权重单份 |
| 模式D（归约） | `\|data_per_core\| + \|reduce_buf\| ≤ 235KB` | 本地数据 + 归约中间 buffer |

> 关键：**方程是推出来的，不是查表查出来的**。拿到一个新策略，先列 buffer 清单（哪些数据在 LDM 里），再标每份的份数（双缓冲？单缓冲？），求和即得方程。不需要背公式。

> 分块设计第一步即用此方程过滤不可行配置，**不需要知道完整问题规模**，只看"一个 tile"。

### 1.3 ACE（脉动阵列，矩阵专用）

| 属性 | 值 | 分核含义 |
| --- | --- | --- |
| 形状 | West 口 128 行 × North 口 32 列，K 粒度 32 | **N 方向被硬件锁死为 32**，不可选 |
| 主频 | **SPE 半频**（ACE = SPE/2），以 `teco-smi` 查询为准。标称 SPE=2.5GHz→ACE=1.25GHz，实际硬件 SPE=2.36GHz→ACE=1.18GHz | 计算密集时 ACE 是瓶颈；频率非固定，性能估算需用实际值 |
| 效率 | K=32→~12T，K=384→~67T，K≥576→饱和 ~75T（@1.25GHz 标称值，实际等比缩放） | 单次连续喂入 K 越大，启动/排空占比越小 |
| 累加器 | fp32 双 buffer，支持 AccumFlag 跨段不清零累加 | **K 维度可时间分片累加，零通信** |
| 写回 | ACMB→LDM 异步，可与下一段 ACE 计算重叠 | 配合双缓冲掩盖写回 |
| 数值稳定性 | 特定频率下（如 2.36GHz）可能出现数值偏差 | 精度验收时关注 `teco-smi` 频率，对照 golden |

> **频率使用原则**：文档中所有 TFLOPS/带宽数值默认基于 SPE=2.5GHz 标称值。实际使用时，以 `teco-smi --query-device=clocks.spe` 查询当前频率，然后等比缩放：`实际值 = 标称值 × (实际SPE频率 / 2.5GHz)`。

### 1.4 DMA 引擎（HBM↔LDM 搬运）

| 约束 | 值 | 分核含义 |
| --- | --- | --- |
| 数量 | 8 个，**按列绑定**（每列 4 SPE 共享 1 个） | 分核要让 loader 分散到**不同列**，避免单引擎过热 |
| 队列深度 | 读写共 ≤ 11，第 12 条延迟暴增 | 每核同时挂起 DMA ≤ 11 |
| 包大小 | 128 B，**PPU 不合并**，地址须 128B 对齐 | 单次搬运 ≥1KB 才高效；4B 请求 = 128B 效率 |
| 最优单次 | ~4 KB/SPE（双缓冲带宽最高） | tile 子块搬运量尽量落在 1~16 KB |
| HBM 行 | 低 19 位同一行，32 核合计 ≤512KB 不跨行 | 每核访问量控制 8~16 KB |

### 1.5 Mesh 网络与 RMA 广播（核间数据复用通道）

| 操作 | 带宽特征 | 分核策略 |
| --- | --- | --- |
| RMA PUT 点对点 | ~53 GB/s，最稳定 | 优先 PUT 非 GET |
| **跨步列广播** `col_ibcast` | 8 引擎全用，@128K/列达 278 GB/s | **B 矩阵沿列广播（高效）** |
| 普通行广播 `row_ibcast` | 仅 1 引擎，~42 GB/s | ❌ 避免 |
| **双对角线行广播** | @128K/行达 188 GB/s | **A 矩阵行广播必用此优化** |

**关键不对称**：列广播天然高效（8 引擎），行广播必须用对角线优化。这直接决定 GEMM 中"A 走行、B 走列"的分工，以及循环顺序把代价更高的列广播放外层。

### 1.6 同步原语（分核协调）

| 原语 | 作用域 | 用途 |
| --- | --- | --- |
| `rt_synchronized_array()` | 全 32 核 | 启动/收尾、全局归约 |
| `rt_synchronized_row()` | 同行 8 核 | A 数据行广播后保证同行都已收到 |
| `rt_synchronized_col()` | 同列 4 核 | B 数据列广播后保证同列都已收到 |
| `rt_synchronized_peer/mask` | 点对点/掩码 | 子组协同、部分核同步 |

> 同步粒度 = 依赖粒度。A 广播后用 row_sync，B 广播后用 col_sync，全局启动/收尾用 array_sync。同步是昂贵操作，**只放必要位置**，且必须在编译期确定（运行期只决定触发几次）。

### 1.7 并发规则（分核时序重叠的前提）

| 组合 | 可否 | 分核利用 |
| --- | --- | --- |
| DMA GET（下网）+ RMA PUT（上网） | ✅ | 双缓冲：DMA 取下一块 ‖ RMA 广播当前块 |
| ACE 计算 + SIMD 计算 | ✅ | 不同硬件单元，可并行 |
| DMA PUT + RMA PUT | ❌ 同向冲突 | 避免 |
| ACE/SIMD 同时访问 LDM | ⚠️ | Bank 错开 |

## 二、RT 接口使用方法论

分核落地依赖 RT（runtime）接口。以下按"识别坐标 → 同步 → 搬运 → 核间通信 → 矩阵计算"给出使用范式。

### 2.1 核坐标与角色识别

```c
int tid = rt_tid;        // _PEN, 0~31
int rid = rt_rid;        // row = tid/8, 0~3
int cid = rt_cid;        // col = tid%8, 0~7
```

分核的第一步永远是**用 tid 推导每个 SPE 的角色**（搬 A / 搬 B / 纯计算 / 归约节点）。角色判定必须是纯算术，编译期可静态分支化。

```python
# 通用角色识别伪代码（GEMM 协作分核）
reply_a, reply_b = 2, 2                      # 每行/每列 loader 数
tid_a = cid % 4                              # 散列到不同列
is_load_a = (tid_a == rid)                   # A-loader：每行 reply_a 个，分布不同列
is_load_b = (满足某种对角散布条件)            # B-loader：每列 reply_b 个，分布不同行
core_idx_a = (tid - rid*8) / 4               # 该 loader 在行内的序号
core_idx_b = (tid < 16) ? 0 : 1              # 该 loader 在列内的序号
```

### 2.2 数据搬运（DMA：HBM↔LDM）

```c
// 阻塞搬运（简单场景）
rt_dma_get(ldm_dst, hbm_src, len);
rt_dma_put(hbm_dst, ldm_src, len);

// 跨步搬运（非连续张量，bsize 建议≥128B）
rt_dma_get_stride(ldm_dst, hbm_src, len, bsize, stride);

// 非阻塞搬运 + reply 计数（流水线必需）
rt_dma_iget(ldm_dst, hbm_src, len, &reply);
while (reply != 1);                          // 手动等待

// 广播搬运（核心：让少数 loader 从 HBM 取数并广播给同行/同列）
rt_dma_col_ibcast_stride(ldm_dst, hbm_src, len, bsize, stride, &reply);  // B 沿列广播
rt_dma_row_ibcast_stride(ldm_dst, hbm_src, len, bsize, stride, &reply);  // A 沿行广播
```

**使用要点**：
- 非阻塞 `iget/iput` + reply 计数是**双缓冲流水线的基础**，阻塞版只能在无重叠时用。
- `col_ibcast` 的 reply 计数等到的不是"本核收到"，而是"列内所有核都收到"，因此广播后**必须配 col_sync**。
- 地址 128B 对齐；单次搬运 1~16 KB；同时挂起 ≤11 条。

### 2.3 核间通信（RMA：LDM↔LDM）

```c
// 点对点（用于归约、数据交换）
rt_rma_iput(l_local, &l_reply, len, r_tid, r_local, &r_reply);
rt_rma_iget(l_local, &l_reply, len, r_tid, r_local, &r_reply);

// 广播/多播（基于 Mesh）
rt_rma_col_ibcast(dst, src, &l_reply, len, &r_reply);   // 列广播（高效）
rt_rma_row_ibcast(dst, src, &l_reply, len, &r_reply);   // 行广播（须对角线优化）

// 集合归约（库已封装树形归约）
swdnnLDMAllReduce_f32(data, buf, len, &l_reply, &r_reply);
```

**使用要点**：
- 优先 `PUT` 而非 `GET`（部分 ring 场景 GET 更慢）。
- 大数据量（≥128KB）点对点 PUT 优于广播。
- 避免 `DMA_GET + RMA 广播` 同时进行（返回通道冲突）。

### 2.4 矩阵计算（ACE）

```c
rt_ace_config_kernel(comptype);                       // 1. 配置 kernel 类型
for (k段 = 0; k段 < k_loops; k段++) {
    rt_ace_load_north(north_ptr + 偏移, 0);           // 2a. 加载 B 到 North 口
    rt_ace_load_west(west_ptr + 偏移, acc_addr,        // 2b. 加载 A 到 West 口
                     accum_flag, xsize, stride,
                     last_flag, precision);            //    ★ load_west 自动触发乘加累加
}
rt_ace_writeback(y_addr, ysize, yrply, precision);    // 3. 写回累加器结果到 LDM
rt_ace_barrier_kernel();                              // 4. ACE 同步
```

**使用要点**：
- `accum_flag=1` 可跨多次 `load_west` 保持累加不清零 → **K 维度时间分片零通信**。
- `last_flag` 标记最后一次 West 加载，触发异步写回；写回可与下一段 ACE 计算重叠。
- K 连续喂入越大效率越高（≥576 饱和），故**优先把 K 做大**而非频繁切 tile。

### 2.5 同步原语用法

```c
rt_synchronized_array();      // 启动/收尾/全局归约前后
... A 行广播 (row_ibcast) ...
rt_synchronized_row();        // 保证同行 8 核都收到 A
... B 列广播 (col_ibcast) ...
rt_synchronized_col();        // 保证同列 4 核都收到 B
... ACE 计算（无需同步，各核独立） ...
```

> 同步点位置在编译期固定，运行期只决定触发次数。原则：**有数据依赖才同步，且用最小作用域同步**（能用 row/col 就不用 array）。

## 三、分核总原则与决策框架

## 三、分核总原则与决策框架

### 3.1 核心因果链：分核是一个决策，同时驱动三件事

> 这是全文方法论的主线。分核**不是**"先切维度、再选访存"两个独立步骤，而是**一个决策同时卡住 ACE 效率曲线、访存方式、访存效率**。选错维度 = ACE 低效 + 通道用错的双重损失。

给定一个算子，"分核决策"= **选哪个维度切给 32 核 + 怎么映射到 4×8 网格**。这一个决策同时决定：

```
分核决策（切哪个维度 + 怎么映射 4×8）
   │
   ├──① 决定 ACE 效率
   │     每核分到的 tile = (BM, BK) → ACE 单次连续喂入 K = BK
   │     → ACE TFLOPS 落在效率曲线哪一点：
   │        BK=32→12T(刚启动)  BK=384→67T(89%)  BK≥576→75T(饱和)
   │     分太细：K 短，ACE 启动/排空占比大，效率塌在低位
   │     分太粗：LDM 装不下（256KB 硬上限）
   │     → 分核粒度必须同时满足「ACE 效率曲线高位」AND「LDM 装得下」
   │
   ├──② 决定访存方式
   │     切哪个维度 → 哪些数据被多个核共享 → 走哪种通道：
   │        切 M（同行核 M 不同）→ A 数据沿行共享 → 行广播
   │        切 N（同列核 N 不同）→ B 数据沿列共享 → 列广播
   │        切 batch/head（互不依赖）→ 无共享 → 各核独立 DMA
   │        切 reduce 维（约化）→ 必须跨核归约 → RMA 树形 reduce
   │
   └──③ 决定访存效率
         访存方式 → 走哪个物理通道 → 带宽差异巨大：
            独立 DMA：8 引擎服务 32 核 → 队列打爆（深度 11），第 12 条延迟暴增
            行广播普通版：仅 1 引擎 → 42 GB/s（差）
            行广播对角线优化：→ 188 GB/s
            列广播跨步版：8 引擎全用 → 278 GB/s（最好）
         → 同样的数据，选错通道带宽差 6 倍以上
```

**关键认知**：①②③ 是同一个分核决策的三个投影，不能分开优化。典型反例——"为了均衡把 M 切得很细"：M 细→每核 BK 不变但 BM 小→ACE 对 M 也敏感利用率降（①↓）；同时 M 切细后行内 loader 搬运量变小→DMA 启动开销占比升（③↓）。一个"均衡"的念头同时伤了两处。

### 3.2 启动模型与 Mesh 维度选择：1维32核 还是 2D 广播？

这是分核的第一个、也是最根本的二选一，由**算法的数据依赖结构**决定：

| 视角 | 用法 | 适用算法 | 代价 |
| --- | --- | --- | --- |
| **1维 32 核** | tid 0~31 线性数组，周期划分，各核独立 DMA | 输出互相独立、数据无共享：逐元素、reduce、逐行归一化 | 零通信、均衡简单；但 GEMM 类数据高度共享时 8 引擎服务 32 核 → 队列打爆，且 Mesh 广播能力闲置浪费 |
| **2D 4×8 广播** | 把"数据共享维度"对齐到 Mesh 物理链路：M 共享→同行、N 共享→同列；少数 loader 取数广播 | 有 M/N 数据复用：GEMM、Conv、线性层 | 需 row/col 同步协调；循环顺序要考虑广播代价不对称 |
| **子网格（局部 2D）** | 32 = GRID×BLOCK，子组内 2D 协作、子组间并行 | batch/head 独立 + 内部有 GEMM：Attention、MoE | 调 BLOCK_SIZE 平衡并行度与子组内复用 |

**判定依据是算法逻辑，不是偏好**：
- 数据**无共享**（逐元素/reduce）→ 用 1维32核；硬上广播纯属浪费（数据本来就各算各的，广播谁？）。
- 数据有 **M 共享或 N 共享**（GEMM 的 A 沿 M 复用、B 沿 N 复用）→ 必须 2D 广播，把复用方向对齐 Mesh 行/列链路；否则要么 32 核重复取同一份数据（DMA 打爆），要么乱用通道。
- **batch/head 独立 + 内部 GEMM**（attention：不同 batch/head 的 Q/K/V 互不依赖，但单头内 QK·V^T 又是 GEMM）→ 子网格：子组间 1维并行切 batch/head，子组内 2D 广播算 GEMM。

> 这条选择直接决定后面访存方式的边界：1维32核下"广播"根本不成立（无共享可广播）；2D 广播下"独立 DMA"会打爆队列。所以 3.2 是 3.3 四要素的前提。

### 3.3 分核四要素决策

> 四要素是 3.1 因果链的具体化：①决定 ACE 效率与访存方式，②③④决定访存效率与通信代价。

```
① 分哪个维度？
   - 优先切"独立的输出维度"（互不依赖），切完无通信。
   - 约化维度（reduce/K）尽量单核内完成，避免核间归约。
   - 受硬件约束：GEMM 的 N 被 ACE 锁死为 32；tile 大小受 LDM 限制。

② 数据复用方向？
   - "只有 M 不同的数据" → 行广播（沿 row）
   - "只有 N 不同的数据" → 列广播（沿 col）
   - 无复用 → 各核独立 DMA

③ 负载均衡？
   - 尽量让每个 SPE 工作量相等；余数按 rid/cid 偏好分配给前若干核。
   - tile 数 < 32 时会出现"空核"，需评估是否改用更细粒度或子组并行。

④ 通信代价？
   - 列广播 > 行广播（代价不对称），把高代价广播放循环外层。
   - 能单核完成就不引入核间通信；必须通信时优先广播而非 reduce。
```

### 3.4 分核模式选择树

```
问题是否有矩阵乘？
├─ 是 → 按 shape 选择 GEMM 策略（见模式B.6 决策树）：
│       ├─ M ≤ 128 → 1×32 或 1D 平坦（GEMV/linear）
│       ├─ N ≤ 32 → 32×1 独立 DMA（split_m）
│       ├─ N ≥ 2048 → 2×16 虚拟网格（M2N16）
│       ├─ M ≥ 4096 → 8×4 虚拟网格（M8N4）
│       ├─ 均衡 M/N → 4×8 广播（N512 或 N256）
│       └─ 均可叠加 Split-K 或 RMA Ring
└─ 否 → 计算是逐元素/逐行独立？
        ├─ 是 → 模式A（周期独立分核）          [激活/归一化/逐元素]
        ├─ 含跨元素归约(reduce dim) →
        │       ├─ reduce dim 小，单核装得下 → 模式A + 模式D（归约在核内）
        │       └─ reduce dim 大，需跨核 → 模式D（分核+核间归约）
        └─ 有 batch/head 独立维度 → 模式C（子网格并行）  [Attention/多head]
```

## 四、五种分核模式

下面五种模式覆盖了绝大多数算子。每种给出**适用场景 → 分核原理 → 伪代码 → 要点**。

### 模式A：周期独立分核（逐行/逐元素）

**适用**：激活、LayerNorm/RMSNorm、逐元素运算、gather/scatter——每个"行"或"切片"独立计算，无核间数据依赖。

**Mesh 维度**：1维 32 核（周期划分），不使用广播。数据无共享 → 广播无从谈起，Mesh 链路对这类算子天然不参与。
**因果链**：切独立输出维(如 NHW)→ 每核算自己的行,数据不共享 → 访存方式=各核独立 DMA → 访存效率靠 cyclic 打满 HBM 通道;ACE 一般不参与(逐元素/SIMD),故因果链停在访存层,无 ACE 效率问题。reduce 维(C)尽量核内完成以避免跨核归约。

**原理**：把张量最外层独立维度（如 NHW）按**周期划分（cyclic）**分给 32 核。每核处理 `tid, tid+32, tid+64, ...`。周期划分（而非块划分）让核组视角地址连续，**打满 HBM 通道**。reduce 维度（如 C）尽量在单核内完成（C 小时一次性读入 LDM；C 大时核内分块双缓冲累加）。

```python
# 模式A 伪代码（以归一化类为例）
def kernel_normalize(arg):
    N_outer = arg.Frist3Dim      # 独立维度（如 NHW）
    C_inner = arg.Last1Dim       # reduce 维度（如 C）
    tid = rt_tid
    if tid >= N_outer: return    # 核数多于任务数，空核退出

    # LDM 预算：C 能否一次读入？
    if C_inner * sizeof(dtype) <= LDM_TILE_BUDGET:
        case_single_pass(arg)    # C 一次读入，每核一行
    else:
        case_double_loop(arg)    # 外层逐行，内层 C 分块累加

def case_single_pass(arg):
    # 周期划分：核 tid 处理行 tid, tid+32, ...
    prefetch(x_buf[0], x + tid*C, C)          # 非阻塞取
    for i in range(tid, N_outer, 32):
        next = i + 32
        if next < N_outer:
            prefetch(x_buf[flag^1], x + next*C, C)   # 预取下一行
        wait(x_buf[flag])                              # 等当前行
        local_stat = reduce_in_core(x_buf[flag], C)   # 核内归约（无通信）
        y_buf[flag] = compute(x_buf[flag], weight, local_stat)
        put(y + i*C, y_buf[flag], C)                  # 写回
        flag ^= 1                                     # 双缓冲翻转
```

**要点**：
- `for i in range(tid, N, 32)` 是本模式的标志性写法，天然负载均衡（余数自动分布）。
- reduce 维度核内完成 → **零核间通信**，是最高效的形态。
- C 太大装不下时，**不要拆 reduce 维度到多核**（会引入归约通信），而是核内分块双缓冲。
- 双缓冲：预取下一行 ‖ 计算当前行，掩盖 DMA。

### 模式B：GEMM 类分核（shape 驱动的多策略）

**适用**：GEMM、BatchGEMM、Conv（im2col 后）、线性层——需要矩阵乘且能装满 ACE。

**核心认知**：GEMM 分核**不是只有 4×8 广播一种**。物理拓扑固定为 4×8，但逻辑映射有 6 种以上，实际代码中还有 1D 平坦策略，共 7 种。选哪种取决于 **M/N/K 的 shape**，不是偏好。

**Mesh 维度**：取决于 shape。均衡 M/N→2D 4×8 广播；N 极小→1D 32×1 无广播；M 极小→1D 1×32 全核广播；大部分 linear 场景→1D 平坦。

#### B.0 统一框架：LDM 预算方程决定一切

所有 GEMM 分核策略的差异，本质是同一个 LDM 预算方程在不同 M/N/K 取值下的不同解。不是"选策略"，而是**给定 shape，解方程**。

**第一步：确定拆分维度（2D 还是 3D）**

```
LDM 预算方程（fp16 无双缓冲）：
  A_tile + B_tile + C_tile ≤ 235KB
  = M2·K·2 + K·32·2 + M2·32·4 ≤ 235KB

给定 M2（由 ACE 效率目标决定），解出 K_max：
  K_max ≈ (235KB - 128·M2) / (4·M2 + 128)
```

| M2 目标 | ACE 效率 | K_max（无双缓冲） | K_max（双缓冲） |
|----------|----------|------------------|-----------------|
| 128 | 饱和 | ~700 | ~350 |
| 64 | 67% | ~1140 | ~570 |
| 32 | 34% | ~1900 | ~950 |

**K ≤ K_max → 2D 拆分（K 不拆，M/N 拆给 32 核）。K > K_max → 3D 拆分（M/N/K 都拆）。**

**第二步：2D 拆分内，按 M/N 比例选网格映射**

K 不拆时，只拆 M 和 N。M/N 的比例决定用什么网格：

| 条件 | 网格 | 为什么 |
|------|------|--------|
| M 极小（≤128） | 1×32 或 1D 平坦 | M 不拆，N 拆 32 路 |
| N 极小（≤32） | 32×1 | N 不拆，M 拆 32 路 |
| N 很大（≥2048） | 2×16 | N 多拆，M 少拆 |
| M 很大（≥4096） | 8×4 | M 多拆，N 少拆 |
| 均衡 | 4×8（N512/N256） | M 拆 4，N 拆 8 |

**第三步：3D 拆分（M/N/K 都拆）**

K > K_max 时，K 必须拆。拆 K 的连锁反应：

```
K 拆给 4 行 → B 不再沿列共享 → B 用 RMA 环传
            → C 是部分和 → RMA 归约 + HBM workspace
            → A 也不再沿行共享 → 32 核独立 DMA
            → M 可以拆给 8 列（M2=128）而非 4 行（M2=32）
            → ACE 效率从 34% 提升到饱和
```

这是**三维拆分**：M/8 列 × N/8 列（rma_loop 轮转）× K/4 行 = 32 核。每核算 `C[32,32] += A[32,384] × B[384,32]`。代价是 B 和 C 都要 RMA 通信，但换来了三个维度都打满并行度 + ACE 饱和。

> 三种策略的对比：

| | 2D（K 不拆） | 2D + Split-K | 3D（K 拆给核） |
|---|---|---|---|
| M 拆分 | 4 行 | 4 行 | 8 列 |
| N 拆分 | 8 列 | 8 列 | 8 列（rma_loop） |
| K 拆分 | 不拆（accum_flag） | 时间分片，归约合并 | 4 行并行，RMA 归约 |
| B 通信 | 列广播 | 列广播 | RMA 环传 |
| C 通信 | 无 | 归约 | RMA 归约 |
| K 上限 | ≤ K_max | 不限 | 不限 |
| 适用 K | 中小 | 大，但不想 3D 开销 | 大，且 M 要推到饱和

#### B.1 4×8 广播（N512 / N256，经典均衡策略）

**适用**：M、N 都较大的均衡 GEMM（M≥512, N≥512）。

**原理**：C[m,n]=ΣA[m,k]·B[k,n]。A 的同一行被同行所有 C 共享 → **沿 row 广播**；B 的同一列被同列所有 C 共享 → **沿 col 广播**。少数"loader"核从 HBM 取数并广播，其余核纯计算。

**N512 vs N256 的区别**：广播方向互换。N512 把 M 拆给 4 行、N 拆给 8 列（A 行广播、B 列广播）；N256 把 M 拆给 8 列、N 拆给 4 行（A 列广播、B 行广播）。选哪个取决于 N 是否够大——N 大时用 N512（列广播高效），N 偏小时用 N256（减少列广播次数）。

```
4×8 网格角色（reply_a=reply_b=2 的典型解）：
  - A-loader：每行 2 个，散布在不同列（用不同 DMA 引擎），对角线放置
  - B-loader：每列 2 个，散布在不同行
  - loader 数=2 是 DMA效率×负载均衡×冗余 的甜点
```

```c
// 模式B.1 实现骨架（N512 方向：M/4行 × N/8列，A行广播 + B列广播）
#define ROWS  4
#define COLS  8
#define ACE_N 32
#define ACE_K 32
#define REPLY_A 2   // 每行 A-loader 数
#define REPLY_B 2   // 每列 B-loader 数

__global__ void kernel_gemm_N512(
    half* A, half* B, float* C, int M, int N, int K,
    int blk_m, int blk_k)
{
    int tid = rt_tid;                     // 0~31
    int rid = rt_rid;                     // row = tid / 8
    int cid = rt_cid;                     // col = tid % 8

    // === 1. 角色识别（编译期静态分支）===
    // A-loader：每行 REPLY_A 个，散布在不同列（用不同 DMA 引擎）
    int tid_a = cid % 4;                  // 散列到 4 列
    int is_load_a = (tid_a == rid);       // 每行 2 个 A-loader
    int core_idx_a = (tid - rid*8) / 4;   // 行内序号 0 或 1

    // B-loader：对角线散布，每列 REPLY_B 个，分布不同行
    int is_load_b = ((rid == 0 && cid < 4) || (rid == 1 && cid >= 4) ||
                     (rid == 2 && cid < 4) || (rid == 3 && cid >= 4));
    int core_idx_b = (tid < 16) ? 0 : 1;

    // === 2. 迭代次数（余数按 rid/cid 偏好分配）===
    int m_loops = M / (blk_m * ROWS) + (M % (blk_m * ROWS) > rid);
    int n_loops = N / (ACE_N * COLS) + ((N / ACE_N) % COLS > cid);
    int k_loops = K / blk_k + (K % blk_k != 0);

    // === 3. 子块大小（loader 间平分）===
    int sub_blk_m = blk_m / REPLY_A + (blk_m % REPLY_A > core_idx_a);
    int sub_blk_n = ACE_N;

    // === 4. LDM 双缓冲布局（编译期确定地址）===
    // 每个 tile 大小：A_tile = blk_m * blk_k * sizeof(half)
    //                B_tile = blk_k * ACE_N * sizeof(half)
    //                C_tile = blk_m * ACE_N * sizeof(float)
    int a_sz = blk_m * blk_k * sizeof(half);
    int b_sz = blk_k * ACE_N * sizeof(half);
    int c_sz = blk_m * ACE_N * sizeof(float);
    __ldm__ half  ldm_A[2][a_sz];   // ping-pong
    __ldm__ half  ldm_B[2][b_sz];
    __ldm__ float ldm_C[2][c_sz];
    int db = 0;  // 双缓冲索引

    // ACE 累加器地址
    __ldm__ float acc[blk_m * ACE_N];

    rt_ace_config_kernel(1);  // 1 = fp16×fp16→fp32

    // === 5. 主循环：N(外) → M(中) → K(内) ===
    for (int n = 0; n < N; n += ACE_N * COLS) {
        for (int m = 0; m < M; m += blk_m * ROWS) {
            // 预取第一个 K 块
            int k_next = 0;
            if (is_load_a) {
                int hbm_off_a = (m + rid * blk_m + core_idx_a * sub_blk_m) * K + k_next;
                rt_dma_row_ibcast_stride(
                    ldm_A[db], A + hbm_off_a,
                    sub_blk_m * blk_k * sizeof(half),  // 总长度
                    sub_blk_m * sizeof(half),           // bsize
                    K * sizeof(half),                   // stride (A 的行跨步)
                    &reply_A);
            }
            if (is_load_b) {
                int hbm_off_b = (k_next) * N + n + cid * ACE_N;
                rt_dma_col_ibcast_stride(
                    ldm_B[db], B + hbm_off_b,
                    blk_k * ACE_N * sizeof(half),
                    ACE_N * sizeof(half),
                    N * sizeof(half),                   // B 的列跨步
                    &reply_B);
            }
            rt_synchronized_row();
            rt_synchronized_col();

            for (int k = 0; k < K; k += blk_k) {
                int k_curr = k;
                k_next = k + blk_k;

                // 预取下一 K 块（非阻塞，仅 loader）
                if (k_next < K) {
                    if (is_load_a) {
                        int hbm_off_a = (m + rid * blk_m + core_idx_a * sub_blk_m) * K + k_next;
                        rt_dma_row_ibcast_stride(
                            ldm_A[db^1], A + hbm_off_a,
                            sub_blk_m * blk_k * sizeof(half),
                            sub_blk_m * sizeof(half),
                            K * sizeof(half), &reply_A);
                    }
                    if (is_load_b) {
                        int hbm_off_b = k_next * N + n + cid * ACE_N;
                        rt_dma_col_ibcast_stride(
                            ldm_B[db^1], B + hbm_off_b,
                            blk_k * ACE_N * sizeof(half),
                            ACE_N * sizeof(half),
                            N * sizeof(half), &reply_B);
                    }
                    rt_synchronized_row();
                    rt_synchronized_col();
                }

                // ACE 计算当前 K 块（accum_flag 跨 k 段累加）
                int accum_flag = (k_curr > 0) ? 1 : 0;  // 首段清零，后续累加
                int last_flag = (k_next >= K) ? 1 : 0;   // 末段触发写回
                int xsize = blk_m / ACE_K;               // West 口加载次数
                int stride = ACE_K * sizeof(half);

                rt_ace_load_north(ldm_B[db], 0);
                for (int xs = 0; xs < xsize; xs++) {
                    rt_ace_load_west(
                        ldm_A[db] + xs * ACE_K * sub_blk_m,
                        acc, accum_flag, xsize, stride,
                        last_flag, 1);  // precision=1 → fp16
                }
                if (last_flag) {
                    rt_ace_writeback(ldm_C[db], blk_m * ACE_N, yrply, 1);
                }
                db ^= 1;  // 翻转双缓冲
            }
        }
        // === 6. 写回 C 到 HBM ===
        int hbm_off_c = m * N + n + cid * ACE_N;
        rt_dma_put(C + hbm_off_c, ldm_C[db], blk_m * ACE_N * sizeof(float));
    }
    rt_ace_barrier_kernel();
}
```

**N256 方向差异**（M/8列 × N/4行，A列广播 + B行广播）：

仅需改三步：
1. 角色分配交换：`is_load_a` 用列广播，`is_load_b` 用行广播
2. `localBM = blk_m / COLS`（M 拆给 8 列），`localBN = blk_n / ROWS`（N 拆给 4 行）
3. 循环顺序：**M 放外层，N 放中层**（因为此时行广播代价更高）

```c
// N256 的关键差异片段
int is_load_a = /* 对角线散布，每列 REPLY_A 个 */;
int is_load_b = (cid % 4 == rid);  // B-loader 沿行分布
int localBM = blk_m / COLS;        // M 拆给 8 列
int localBN = blk_n / ROWS;        // N 拆给 4 行
// 循环：M(外) → N(中) → K(内)
for (int m = 0; m < M; m += blk_m * COLS) {
    for (int n = 0; n < N; n += ACE_N * ROWS) {
        for (int k = 0; k < K; k += blk_k) { ... }
    }
}
```

**要点**：
- **循环顺序 N→M→K**：K 必须在 (M,N) 之内（ACE 单累加器约束）；列广播代价 > 行广播，故 N 放外层减少列广播重复次数。
- **loader=2 甜点**：太少单点瓶颈，太多单次传输过小效率低。
- **K 时间分片（非空间 SplitK）**：用 `accum_flag` 在 ACE 内 fp32 累加，零核间通信、零额外 LDM。
- **双缓冲条件**：`T_dma < 0.8·T_ace` 时启用，DMA 被 ACE 完全掩盖。
- **重复加载可接受**：LDM 双缓冲会覆写导致 A/B 重复 load，但只要 ACE 算力能掩盖 DMA，重复多少次都无所谓——优化重点是**确保 T_dma ≪ T_ace**，而非消除重复。

#### B.2 1D 平坦分核（M≤32 的 linear 主力）

**适用**：M 较小（≤32）的线性层/权重量化 GEMM。这是实际代码中使用最广泛的策略，覆盖所有 weight-only 量化、group GEMM、batch GEMM 场景。

**原理**：32 核当作一维数组，N 维度按 `N_PER_LOOP = 32核 × ACE_N(32) = 1024` 拆分。每核独立 DMA 取自己的 B 片段，A 矩阵全核复制。没有 2D 网格的 row/col 同步。

```c
// 模式B.2 实现骨架（1D 平坦分核）
#define CORE_NUM     32
#define ACE_N        32
#define ACE_K        32
#define K_BLOCK_NUM  4     // K 维度 DMA 分段数

__global__ void kernel_linear_1d(
    half* A, half* B, float* C, int M, int N, int K)
{
    int tid = rt_tid;                          // 0~31
    int N_PER_LOOP = CORE_NUM * ACE_N;         // 1024

    // A 矩阵全量读入（M≤32，LDM 装得下）
    int a_sz = M * K * sizeof(half);
    __ldm__ half A_ldm[a_sz];
    rt_dma_get(A_ldm, A, a_sz);

    // B 和 C 的 LDM 空间
    int b_sz = ACE_N * K * sizeof(half);
    int c_sz = M * ACE_N * sizeof(float);
    __ldm__ half  B_ldm[b_sz];
    __ldm__ float C_ldm[c_sz];
    __ldm__ float acc[M * ACE_N];

    rt_ace_config_kernel(1);
    rt_synchronized_array();

    for (int n_outer = 0; n_outer < N; n_outer += N_PER_LOOP) {
        int n_start = n_outer + tid * ACE_N;
        int n_len = (n_start + ACE_N <= N) ? ACE_N : (N - n_start);
        if (n_start >= N) continue;

        // B 矩阵各核取自己的列片段
        rt_dma_get(B_ldm, B + n_start * K, n_len * K * sizeof(half));

        // K 维度分块喂 ACE
        int k_per_block = K / K_BLOCK_NUM;
        for (int kb = 0; kb < K_BLOCK_NUM; kb++) {
            int k_off = kb * k_per_block * ACE_N * sizeof(half);
            int accum_flag = (kb == 0) ? 0 : 1;
            int last_flag = (kb == K_BLOCK_NUM - 1) ? 1 : 0;
            int xsize = M / ACE_K;

            rt_ace_load_north(B_ldm + k_off, 0);
            for (int xs = 0; xs < xsize; xs++) {
                rt_ace_load_west(
                    A_ldm + k_off + xs * ACE_K * M,
                    acc, accum_flag, xsize,
                    ACE_K * sizeof(half), last_flag, 1);
            }
            if (last_flag) {
                rt_ace_writeback(C_ldm, M * ACE_N, yrply, 1);
            }
        }
        // 写回 C
        rt_dma_put(C + n_start, C_ldm, n_len * M * sizeof(float));
    }
    rt_ace_barrier_kernel();
}
```

**要点**：
- **无 row/col 同步**：各核独立，只有 array_sync 做全局启停。
- **M 全复制**：M ≤ 32 时 A 矩阵很小，直接全量读入 LDM，无需广播。
- **N 周期拆分**：`N_PER_LOOP = 1024`，外层循环遍历 N。
- 当 M > 32 时，可改用 M_CHUNK 分段：`for (int m_chunk = 0; m_chunk < M; m_chunk += 32)`，每 32 行一批处理。

#### B.3 虚拟网格（2×16 / 8×4 / 32×1 / 1×32）

当 M 或 N 极端不对称时，4×8 均衡拆分会导致某方向 tile 过小（ACE 效率低）或过大（LDM 装不下）。此时用虚拟网格重映射 `tid→(rid,cid)`：

**2×16（N 很大，如 N≥2048）**：M 只拆 2 路，N 拆 16 路，A 行广播 + B 各核独立 DMA。

```c
// 2×16 虚拟网格映射
int rid = (tid >> 3) & 0x01;                       // 2 行: tid/8 的奇偶
int cid = ((tid >> 4) << 3) + (tid & 0x7);         // 16 列: 高4位组 + 低3位
int localBM = blk_m / 2;                           // M 拆 2 路
int localBN = blk_n / 16;                          // N 拆 16 路
// A 走行广播（dma_row_ibcast），B 各核直接 dma_iget
// 循环：N(外) → M(中) → K(内)
```

**8×4（M 很大，如 M≥4096）**：M 拆 8 路，N 拆 4 路，A 列广播 + B 行广播。

```c
// 8×4 虚拟网格映射
int rid = tid % 8;                                 // 8 行
int cid = tid / 8;                                 // 4 列
int localBM = blk_m / 8;                           // M 拆 8 路
int localBN = blk_n / 4;                           // N 拆 4 路
// A 走列广播（dma_col_ibcast），B 走行广播（dma_row_ibcast）
// 循环：M(外) → N(中) → K(内)
```

**32×1（N 极小，如 N≤32）**：N 不拆分，每核处理连续的 M 片段。**无广播**，这是唯一不使用 Mesh 广播能力的 GEMM 策略。

```c
// 32×1 映射：每核独立，无广播
int tid = rt_tid;                                  // 直接用 tid 0~31
int m_per_core = 128;                              // 每核处理 128 行 M
int core_start_m = tid * m_per_core;
// A 和 B 各核独立 dma_iget 取数，无 row/col 同步
// 循环：M(外，按 32 核步进) → K(内，ACE 累加)
for (int m_base = 0; m_base < M; m_base += m_per_core * 32) {
    int m_start = m_base + core_start_m;
    // 各核独立 DMA 取 A 和 B
    rt_dma_iget(A_ldm, A + m_start * K, m_per_core * K * sizeof(half), &reply);
    rt_dma_iget(B_ldm, B, N * K * sizeof(half), &reply);
    // ACE 计算，accum_flag 累加 K
    // 写回 C
}
```

**1×32（M 极小，如 M≤128）**：M 不拆分，A 全核广播，N 拆 32 路。

```c
// 1×32 映射：M 全复制，N 拆给 32 核
int tid = rt_tid;                                  // 0~31
int n_per_loop = ACE_N;                            // 每核 32 列 N
// A 全核广播：一个核 dma_iget 后 rma_col_ibcast 给全核
// B 各核独立 dma_iget 取自己的 N 片段
// 无 row/col 同步，仅 array_sync
```

**要点**：
- 虚拟网格的本质是**重映射 `tid→(rid,cid)`**，不改物理拓扑。映射函数在编译期确定，无运行时开销。
- 选哪个虚拟网格由 shape 决定：**把大的维度多拆，小的维度少拆**。
- 每种虚拟网格的其余代码（ACE 调用、双缓冲、LDM 布局）复用 B.1 的骨架，仅改网格映射和广播方向。

#### B.4 RMA Ring 通信

**适用**：均衡 M/N 的 GEMM，K 维度需要跨核协作但不希望拆分 K（避免归约）。

**原理**：B 矩阵在 4 行核之间通过 **RMA 点对点环传**轮转。每行核算完一段 K 后，把 B 通过 RMA PUT 传给下一行，自己接收上一行的 B 继续算。

```c
// 模式B.4 实现骨架（RMA Ring 通信）
#define ROWS 4
#define COLS 8

__global__ void kernel_gemm_ring(half* A, half* B, float* C, int M, int N, int K)
{
    int tid = rt_tid, rid = rt_rid, cid = rt_cid;
    int localBM = M / ROWS;                    // M 拆给 4 行
    int localBN = ACE_N;                       // N 每核 32

    // B 矩阵分 4 段，每行初始持有不同的 K 段
    int k_per_ring = K / ROWS;                 // 每段 K 大小
    int k_start = rid * k_per_ring;            // 本行初始 K 段

    __ldm__ half  A_ldm[localBM * K * sizeof(half)];
    __ldm__ half  B_ldm[k_per_ring * localBN * sizeof(half)];
    __ldm__ half  B_remote[k_per_ring * localBN * sizeof(half)];  // 接收下一行的 B
    __ldm__ float C_ldm[localBM * localBN * sizeof(float)];
    __ldm__ float acc[localBM * localBN];

    int l_reply = 0, r_reply = 0;
    rt_synchronized_array();

    // 初始化：各核取自己的 A 和第一段 B
    rt_dma_iget(A_ldm, A + rid * localBM * K, localBM * K * sizeof(half), &l_reply);
    rt_dma_iget(B_ldm, B + k_start * N, k_per_ring * N * sizeof(half), &l_reply);
    while (l_reply != 2);
    rt_ace_config_kernel(1);

    for (int ring = 0; ring < ROWS; ring++) {
        // ACE 计算当前持有的 K 段
        int accum_flag = (ring == 0) ? 0 : 1;
        int last_flag = (ring == ROWS - 1) ? 1 : 0;
        int xsize = localBM / ACE_K;

        rt_ace_load_north(B_ldm, 0);
        for (int xs = 0; xs < xsize; xs++) {
            rt_ace_load_west(A_ldm + xs * ACE_K * localBM,
                             acc, accum_flag, xsize,
                             ACE_K * sizeof(half), last_flag, 1);
        }
        if (last_flag) {
            rt_ace_writeback(C_ldm, localBM * localBN, yrply, 1);
        }

        // RMA Ring: 把 B 传给下一行，接收上一行的 B
        if (ring < ROWS - 1) {
            int next_rid = (rid + 1) % ROWS;
            int next_tid = next_rid * COLS + cid;
            l_reply = 0; r_reply = 0;
            rt_rma_iput(B_ldm, &l_reply, k_per_ring * localBN * sizeof(half),
                        next_tid, B_remote, &r_reply);
            while (l_reply != 1 || r_reply != 1);
            // 交换 buffer
            swap(B_ldm, B_remote);
        }
    }
    // 写回 C
    rt_dma_put(C + rid * localBM * N, C_ldm, localBM * localBN * sizeof(float));
    rt_ace_barrier_kernel();
}
```

**要点**：
- 与广播的区别：广播是"一份数据同时给多核"，环传是"数据在核间接力"。
- 环传接收侧流量有界（每核只收 1 块），可与 DMA_GET 时序重叠。
- 代价：ROWS 轮同步，比 accum_flag 时间分片多 ROWS-1 次通信。
- 适用判断：K 太大 accum_flag 装不下，但又不想引入 split-K 的归约开销时使用。

#### B.5 Split-K（空间拆分 K 维度）

**适用**：K 太大，LDM 装不下单核的完整 K tile。

**原理**：把 K 维度拆成 `split_num` 段（2/4/8/16/32），每核只算一段，最后 RMA 归约合并各段的部分和。这是**空间 SplitK**，与 accum_flag 的**时间分片**互补。

```
Split-K 决策：
  优先 accum_flag 时间分片（零通信、零额外 LDM）
  → LDM 装不下时 → 空间 SplitK（RMA 归约，有通信代价但可接受）
  split_num = K / max_ldmK，其中 max_ldmK 由 LDM 预算方程反推
```

**要点**：
- 不是"万不得已才用"——大 K 场景下是标准策略。
- 代价：引入 RMA 归约（log₂(split_num) 步），且需要额外 LDM 存部分和。
- 与 accum_flag 时间分片的关系：**互补而非替代**。时间分片在同一核内串行累加；空间 SplitK 跨核并行再归约。
- 实现上复用基础 GEMM 策略（B.1~B.3）的骨架，仅在外层加 K 段循环和最后的归约步骤（模式D）。

#### B.6 三维拆分（M/N/K 都拆给 32 核）

**触发条件**：K > K_max（LDM 预算方程在给定 M2 下的解）。即 M2 推到 ACE 效率目标值后，LDM 装不下完整的 K。

**原理**：M 拆给 8 列，N 拆给 8 列（通过 rma_loop 轮转），K 拆给 4 行。`M/8 × N/8 × K/4 = 32 核`。K 拆了，B 不再沿列共享，必须 RMA 环传；C 是部分和，必须 RMA 归约，跨 K1 tile 还需 HBM workspace 持久化。

**与 2D 拆分的本质区别**：

| | 2D（K 不拆） | 3D（K 拆给核） |
|---|---|---|
| 拆分维度 | M + N | M + N + K |
| B 通信 | 列广播（高效） | RMA 环传（点对点） |
| C 通信 | 无 | RMA 行归约 |
| K 累加 | accum_flag（零通信） | RMA 归约 + workspace |
| K 上限 | ≤ K_max（~350~700） | 不限 |
| ACE 效率 | M2=32（34%） | M2=128（饱和） |
| 适用 | K 中小 | K 大，且需 M2 推大 |

**推导过程**：

```
Step 1: LDM 预算判定
  M2 目标=128（ACE 饱和），K_max≈700（无双缓冲）
  实际 K=12288 ≫ 700 → K 必须拆

Step 2: K 拆给 4 行
  K2 = K/4 = 384，A_tile = 128×384×2 = 96KB ✅
  K 拆了 → B 不再沿列共享 → 列广播不成立

Step 3: B 的通信方式
  同列 4 核 K 段不同 → 不能广播
  → 每核独立 DMA 取自己的 B 片段
  → 同行 8 核之间 RMA 环传交换 B

Step 4: C 的归约
  4 行各算一段 K → C 是部分和
  → 同列 4 行 RMA 归约
  → 跨 K1 tile 累加溢出到 HBM workspace

Step 5: M 的拆分
  K 拆给 4 行后，M 可以拆给 8 列（而非 4 行）
  → M2=128（ACE 饱和），而非 M2=32
```

**伪代码骨架**：

```c
// 3D 拆分：M/8列 × N/8列 × K/4行
#define ROWS 4, COLS 8
int rid = rt_rid, cid = rt_cid, tid = rt_tid;
int M2 = M1_TILE / COLS;     // M 拆 8 列，每列 128
int K2 = K1_TILE / ROWS;     // K 拆 4 行，每行 384
int N2 = ACE_N;              // N 每核 32

// A: 32 核独立 DMA（无广播）
rt_dma_iget(A_ldm, A + tid * M2*K2, M2*K2*sizeof(half), &reply);

// B: 32 核独立 DMA（无广播）
rt_dma_iget(B_ldm, B + tid * N2*K2, N2*K2*sizeof(half), &reply);

// N 循环（rma_loop 轮转 8 列）
for (int rma_loop = 0; rma_loop < COLS; rma_loop++) {
    // B 同行环传：cid 传给 (cid-1)
    rt_rma_iput(B_ldm, ..., (rid*COLS + (cid-1)%COLS), B_remote, ...);
    
    // ACE 计算
    rt_ace_load_north(B_ldm, 0);
    rt_ace_load_west(A_ldm, acc, accum_flag, ...);
    rt_ace_writeback(C_ldm, ...);
    
    // C 跨行归约：发给同列其他 3 行
    rt_rma_iput(C_ldm + (rid+1)%4*BLK, ..., (tid+8)%32,  C_rma[0], ...);
    rt_rma_iput(C_ldm + (rid+2)%4*BLK, ..., (tid+16)%32, C_rma[1], ...);
    rt_rma_iput(C_ldm + (rid+3)%4*BLK, ..., (tid+24)%32, C_rma[2], ...);
    
    // SIMD 累加 4 行部分和
    for (i = 0; i < BLK; i += 128)
        C_final[i] = C_my[i] + C_rma[0][i] + C_rma[1][i] + C_rma[2][i];
    
    // 最后一轮 K → 直接写 HBM；否则写 workspace
    if (is_last_K_tile)
        dma_put(C_hbm, C_final, ...);
    else
        dma_put(workspace, C_final, ...);  // 下轮 K tile 读回累加
}
```

#### B.7 GEMM 分核决策树

```
GEMM 分核决策（从 LDM 预算方程出发）
│
├─ Step 1: 算 K_max
│   K_max ≈ (235KB - 128·M2) / (4·M2 + 128)
│   M2 越小 → K_max 越大，但 ACE 效率越低
│
├─ K ≤ K_max → 2D 拆分（K 不拆）
│   ├─ M ≤ 128 → 1×32 或 1D 平坦
│   ├─ N ≤ 32  → 32×1，各核独立 DMA
│   ├─ N ≥ 2048 → 2×16 虚拟网格
│   ├─ M ≥ 4096 → 8×4 虚拟网格
│   └─ 均衡 → 4×8 广播（N512/N256）
│
└─ K > K_max → K 必须拆
    ├─ K 拆给多核并行（3D 拆分）→ M2 可推到 128，ACE 饱和
    │   代价：B RMA 环传 + C RMA 归约 + workspace
    └─ 或 K 时间分片（Split-K）→ 保留 2D 广播，M2 较小
        代价：RMA 归约，但 B 仍用广播
```

> **不存在"GEMM 就用 4×8 广播"这种万能公式**——所有策略都是 LDM 预算方程在不同 shape 下的解。

### 模式C：子网格并行（batch/head 独立维度）

**适用**：FlashAttention、Multihead Attention、MoE gating、batch 独立的算子——存在大量相互独立的"任务单元"（batch×head）。

**Mesh 维度**：子网格(局部 2D)。32=GRID×BLOCK:子组间 1维并行切 batch/head(互不依赖),子组内 2D 协作算单头的 GEMM(QK·V^T)。
**因果链**：batch/head 独立 → 子组间无通信、周期领取任务(③均衡);子组内是 GEMM → 复用模式B 的因果链(BLOCK_SIZE 决定子组 tile 的 ACE 效率,子组内 K/V 沿 BLOCK 广播或各自取)。BLOCK_SIZE 是枢纽:太小子组内无复用、DMA 打满;太大 batch/head 并行度低、长尾拖慢。

**原理**：把 32 SPE 切成若干**子组**，子组间空间并行处理不同任务单元，子组内协作（广播/归约）处理一个任务。`32 = GRID_NUM × GRID_SIZE × BLOCK_SIZE`。

```python
# 模式C 伪代码（Attention 子网格并行）
def kernel_attention(params):
    # 32 = GRID_NUM * GRID_SIZE * BLOCK_SIZE（编译期模板参数）
    TID  = rt_tid % BLOCK_SIZE                 # 子组内线程
    BID  = (rt_tid // BLOCK_SIZE) % GRID_SIZE  # 并行 batch 槽
    GID  = rt_tid // (BLOCK_SIZE * GRID_SIZE)  # 网格号
    GRID_NUM = 32 // (BLOCK_SIZE * GRID_SIZE)

    rt_synchronized_array()
    # 任务单元 = batch_size × num_heads，子组周期领取
    for mission in range(GID*GRID_SIZE + BID,
                         batch_size * num_heads,
                         GRID_NUM * GRID_SIZE):
        head_id  = mission % num_heads
        batch_id = mission // num_heads
        # 子组内 BLOCK_SIZE 核协作算一个 (batch, head) 的 attention
        # 每个 core 处理 SEQLEN_PER_CORE 行 Q，K/V 沿子组广播或各自 DMA
        attention_one_head(ldm_q, ldm_k, ldm_v, TID, BLOCK_SIZE, ...)
    rt_synchronized_array()
```

**要点**：
- 子组大小 `BLOCK_SIZE` 是关键调参：太小（如 1）则无核内复用、DMA 打满；太大（如 32）则 batch/head 并行度低、长尾任务拖慢。通常 4/8/16。
- 子组内若需 reduce（如 attention 的 softmax 跨行 max/sum），用子组级树形归约（见模式D）。
- `mission_id` 周期领取保证子组间负载均衡，长尾任务由 GRID_NUM 自然分摊。

### 模式D：分核 + 核间归约

**适用**：reduce/sum/mean、softmax 跨核、allreduce——约化维度必须跨核时。

**Mesh 维度**：1维 32 核 + RMA 树形归约(基于 2D Mesh 全连接,但逻辑上按 1维数组组织)。
**因果链**：reduce 维跨核 → 必须通信,无广播可复用(约化是"合并"非"分发")→ 访存方式=RMA 树形 reduce(②)→ 访存效率靠 log₂32=5 步压缩通信步数、每步配 array_sync(③)。ACE 不参与(归约是加法非矩阵乘)。能避免就避免:reduce 维优先单核装下(退回模式A),只有装不下才跨核。

**原理**：每个 SPE 算本地 partial sum，再用 **RMA 树形/蝶形归约** 合并到全核，最后广播结果。32 核归约 = log₂32 = 5 步。

```python
# 模式D 伪代码（树形 AllReduce，5 步合并 + 1 步广播）
def allreduce(data, buf, n):
    rid, cid, tid = rt_rid, rt_cid, rt_tid
    rt_synchronized_array()
    # 步1：列内配对  cid%2==0 ← cid+1
    if cid % 2 == 0:
        rma_put(buf, data, n, tid+1); wait(); data += buf
    else:
        rma_recv(); wait()
    # 步2：cid%4==0 ← cid+2
    # 步3：cid==0  ← cid+4   （列归约完成，结果在 (rid,0)）
    # 步4：cid==0 且 rid%2==0 ← rid+8
    # 步5：cid==0 且 rid==0 ← rid+16  （全局归约完成，结果在 core0）
    rt_synchronized_array()
    # 步6：core0 广播结果给全核
    if tid == 0:
        rma_bcast(data, buf, n, ...)
    wait(); rt_synchronized_array()
```

**要点**：
- 归约是**最贵的分核操作**，能避免就避免：reduce 维度优先单核内完成（模式A），只有装不下才跨核。
- 用 RMA PUT 而非 GET；每步配 `array_sync` 保证依赖。
- 归约数据量越大代价越高，尽量在 **LDM 中归约小 buffer**，不要对大张量直接全核归约。
- 提供 `_perf` 版本（更细流水）供大数据量使用。

### 模式E：卷积 im2col 分块 + 权重广播

**适用**：Conv2D/Conv3D 前向反向——本质是 im2col→GEMM，但有权重共享特性。

**Mesh 维度**：2D 广播(权重共享)。所有输出位置共享同一卷积核 → 权重沿核广播(一次取数全核复用);输入 im2col patch 各核按空间 tile 分。
**因果链**：空间 tile=(block_e,block_f)分核 → tile 限 ACE 单次计算量(e×f≤128)且 LDM 装得下(①) → 权重共享走广播、输入各核取(②)→ 权重广播用 col_ibcast 高效、输入 im2col 跨步取(③);分块搜索先推高 block_f(ACE 对 M 敏感)再扩 e/c。是模式B 在"权重强共享"场景的特化。

**原理**：输出按 (block_e, block_f) 分块（空间 tile），权重沿核广播（所有输出位置共享同一卷积核）。分块大小由 **LDM 预算 + ACE 限制**（如 `block_e × block_f ≤ 128`）联合搜索。

```python
# 模式E 伪代码（卷积分块）
def kernel_conv(arg):
    # 主机侧 metric 已搜索最优 (block_e, block_f, deal_weight_block_c)
    # 约束：read_all_c ≤ ldm_space 且 block_e*block_f ≤ 128（ACE）
    unit_block_m = 32                         # ACE M 粒度
    for 输出空间分块 (e, f):
        # 1. 广播权重到全核（权重共享，用 row/col 广播）
        rt_dma_col_ibcast(weight_buf, weight + off, ...)
        rt_synchronized_col()
        # 2. 各核取自己负责的输入 patch（im2col）
        rt_dma_iget_stride(x_buf, x + im2col_off, len, bsize, stride, &reply)
        # 3. ACE 做 im2col × weight 的 GEMM（复用模式B 的 ACE 流程）
        ace_cal(x_buf, weight_buf, y_buf, block_e, block_f)
        # 4. 写回输出 tile
        rt_dma_iput(y + out_off, y_buf, ...)
```

**要点**：
- 分块搜索优先推高 `block_f`（受 F 上限），再扩 `block_e`（受 ACE `e×f≤128`），最后扩 `deal_weight_block_c`（受 LDM）。
- 权重广播 = 一次取数全核复用，是卷积相对纯 GEMM 的优化点。
- `double_broad_cast` 标志控制是否双路权重广播以利用更多 DMA 引擎。

## 五、通用分核设计流程

实现一个新算子时，按以下七步推导分核方案。前六步**编译期可确定**（不依赖具体 M/N/K 数值，只看 tile 结构），第七步运行期验证。

### Step 1：确定计算结构与数据复用方向

```
画出算子的数据流：
  - 输出 C 依赖哪些输入？依赖关系是 M-共享 / N-共享 / 约化？
  - 哪些数据"只有 M 不同"→ 行广播；"只有 N 不同"→ 列广播。
  - 是否有 batch/head 独立维度 → 考虑子网格并行。
  - 是否含 reduce → reduce 维度能否单核装下？
→ 选定分核模式（A/B/C/D/E 之一或组合）。
```

### Step 2：LDM 预算与分块大小

```
对候选 tile (BM,BN,BK) 解 LDM 预算方程：
  LDM = 2·BM·BK·dAB + 2·BK·BN·dAB + BM·BN·dC ≤ 235KB
约束：
  - BN == 32（ACE 锁死，GEMM 类）
  - BK % 32 == 0（ACE K 粒度）
  - BM ≤ 128（ACE West 上限），偶数（支持 reply=2 平分）
策略：先推高 BM（ACE 对 M 敏感），到上限后剩余空间给 BK；
      仍不够 → K 时间分片（缩小单次 BK，靠 accum_flag 累加）。
```

### Step 3：选择分核模式与网格划分

```
- 32 核全协作（4×8）→ 模式B
- 32 核周期独立 → 模式A
- 子组并行 → 模式C，确定 BLOCK_SIZE（4/8/16），余数评估空核
- 含跨核归约 → 叠加模式D
```

### Step 4：角色分配与负载均衡

```
- loader 角色用 CSP 约束求解：每行 reply_a 个 A-loader 散布不同列，
  每列 reply_b 个 B-loader 散布不同行，A/B loader 不重叠。
- 迭代次数 = ⌈dim / (tile × 网格)⌉，余数按 rid/cid 偏好分配：
  loops_core = dim // (tile*grid) + (dim % (tile*grid) > rid)
- 评估空核比例：若 tile 数 < 32，考虑改细粒度或子组并行。
```

### Step 5：流水线与双缓冲

```
估算 T_ace(BM,BK) 与 T_dma(sub_blk)，若 T_dma < 0.8·T_ace：
  → 双缓冲（A/B ping-pong，C 单缓冲），DMA 被 ACE 掩盖
否则 → 简单串行，或加大 tile 让 ACE 占比上升
- 把 DMA/RMA/ACE/SIMD 流量错开到 LDM Bank0/Bank1。
```

### Step 6：同步点设计

```
编译期固定同步位置：
  - 启动/收尾：array_sync
  - A 行广播后：row_sync
  - B 列广播后：col_sync
  - 归约步骤间：array_sync
运行期只决定触发几次（=循环次数）。原则：最小作用域，有依赖才同步。
```

### Step 7：运行期验证与调优

```
- 用 rt_time_cycle() 分段计时，定位 DMA wait / ACE / 同步占比。
- 静态拍数估算（P0 计算 vs P1 访存）锁定热点方向，再用 profiler 升级结论。
- autotuner 在 {BM, BK, ROWS×COLS, BLOCK_SIZE, reply, split_k} 离散空间搜索，
  用编译期 cost model 打分（无需真机），best 配置生成 kernel。
```

## 六、分核相关的优化要点

> 本章只保留**与分核切法/通信形态直接相关**的要点；纯访存时序、DMA 队列、LDM Bank 错开、流水线掩盖、ACE 效率等见独立文档 `访存与流水线优化.md`。

### 6.1 切法对 HBM 访问的影响

- 用**周期划分（cyclic）**而非块划分，让核组视角地址连续，打满 16 通道。
- 每核访问量控制 8~16 KB（32 核合计 ≤512KB 不跨 HBM 行）——这是分核粒度的上限约束，不是访存技巧。

### 6.2 通信形态选择：环传 vs 列广播

分核四要素之一是"数据怎么在核间流动"。同一份共享数据，可用两种形态分发，代价差异大：

| 形态 | 接收侧流量 | 适用 | 备注 |
| --- | --- | --- | --- |
| **点对点环传** `rma_iput` | 每核只收 1 块，有界 | 数据需在核间依次接力、且接收侧要与 DMA_GET 重叠 | 接收 fan-in 轻，可与 DMA_GET 时序重叠 |
| **列广播** `col_ibcast` | 多对一下行汇聚 | 一份广播给整列 | 接收侧 fan-in 重，与 DMA_GET 同时易争用返回通路 |
| **行广播** `row_ibcast` | — | 一份广播给整行 | 普通版仅 1 引擎 42 GB/s，**必须用双对角线优化**（188 GB/s） |

要点：
- "数据沿行/列复用"是分核决策（A 走行、B 走列），但**具体用广播还是环传**是通信形态选择。
- 当某核一边 DMA_GET（下行）一边还要接收 RMA（下行）时，两者共享返回通路：**点对点环**接收流量有界可接受，**列广播**接收 fan-in 重易拥塞。→ 需要重叠时优先环传或错峰。
- 大数据量（≥128KB）单点对点 PUT 优于广播。

### 6.3 分核均衡

- 余数按 rid/cid 偏好分配，避免某核多算一轮形成长尾。
- tile 数远大于 32 时周期划分天然均衡；tile 数接近/小于 32 时评估空核与子组并行。
- 子组并行时 `GRID_NUM` 应整除 32 且能整除任务数，减少尾任务。

## 八、常见分核陷阱与规避

> 仅列分核层面的陷阱；LDM Bank 竞争、DMA/RMA 同向时序冲突等访存问题见 `访存与流水线优化.md`。

1. **reduce 维度跨核拆分**：能单核装下就别拆，跨核归约代价远大于单核循环。→ 优先核内分块双缓冲。

2. **行广播用普通 `row_ibcast`**：仅 1 引擎 42 GB/s。→ 必须用双对角线优化（188 GB/s）。

3. **所有核同时独立 DMA**：8 引擎队列打爆，第 12 条延迟暴增。→ 用 loader+广播/环传，少数核取数。

4. **空间 SplitK 当默认**：引入 RMA reduce + LDM 存 partial + 精度风险。→ 优先 K 时间分片（accum_flag 零通信），仅 LDM 装不下且通信可接受才空间 SplitK。

5. **K 放循环最外层**：需存中间部分和，LDM 装不下。→ K 必须在 (M,N) 之内。

6. **同步用得过粗**：处处 array_sync 引入全核停顿。→ 用最小作用域 row/col_sync。

7. **空核不退出**：tile 数 < 32 时空核仍跑循环或访问非法地址。→ `if tid >= N: return` 守卫。

8. **分核只看并行不看均衡**：余数全堆给一核 → 长尾。→ 偏好式余数分配 + autotuner 验证。

9. **通信形态选错**：接收侧要与 DMA_GET 时序重叠时，误用列广播（fan-in 重）而非点对点环传（流量有界）。→ 见 6.2。

10. **GEMM 只用 4×8 广播，不看 shape**：极端 M/N 下 4×8 均衡拆分导致 tile 过小/过大。→ N 很大用 2×16，M 很大用 8×4，N 极小用 32×1 独立 DMA，M 极小用 1×32 或 1D 平坦。见模式B.6 决策树。

11. **M≤32 的 linear 还上 2D 广播**：M 太小时 4 行拆分导致每核 tile 过小，2D 广播的 row/col 同步开销反而成为瓶颈。→ 应默认用 1D 平坦策略，零同步开销。见模式B.2。
