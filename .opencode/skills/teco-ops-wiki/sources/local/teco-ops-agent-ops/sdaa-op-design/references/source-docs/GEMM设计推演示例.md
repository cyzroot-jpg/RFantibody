# GEMM 设计推演示例：M=4096, N=4096, K=4096, fp16

> 用 `算子设计方法论.md` 六阶段流程，完整走一遍。每一步输出一个数字，驱动下一步决策。

---

## 阶段一：算子特征

```
C[4096, 4096] = Σ A[4096, 4096] × B[4096, 4096]
精度：fp16×fp16→fp32
依赖：M 独立、N 独立、K 约化
无 batch/head 维度 → 32 核全协作
```

---

## 阶段二：硬件约束（不可变公理）

```
LDM = 235KB
ACE_N = 32（锁死）
ACE West = 128 行
ACE_K 粒度 = 32
SPE = 32 核，4×8 网格
DMA = 8 引擎，按列绑定
```

---

## 阶段三：LDM 预算（核心决策点）

**方程**（fp16，无双缓冲）：

```
A_tile = M2 × K × 2B
B_tile = K × 32 × 2B
C_tile = M2 × 32 × 4B

LDM_used = M2·K·2 + K·32·2 + M2·32·4 ≤ 235KB

解：K_max(M2) = (235×1024 - 128·M2) / (2·M2 + 64)
```

| M2 | K_max | ACE 效率 | K=4096 能否装下？ |
|----|-------|----------|------------------|
| 128 | 700 | 饱和 | ❌ 4096 ≫ 700 |
| 64 | 1210 | 67% | ❌ 4096 ≫ 1210 |
| 32 | 1848 | 34% | ❌ 4096 ≫ 1848 |

**结论：K=4096 > 所有 M2 的 K_max → 2D 拆分不可行 → 必须走 3D 方向。**

---

## 阶段四：分核方案推导

### 4.1 3D 拆分：K 拆给 4 行

```
K 拆给 4 行 → K2 = K1/4
K2 仍需 ≤ K_max(M2)，否则 K1 也要拆多轮

M2=128 → K2_max=700  → K1_max=2800 → ceil(4096/2800)=2 轮 → K1=2048, K2=512
M2=64  → K2_max=1210 → K1_max=4840 → 1 轮           → K1=4096, K2=1024
M2=32  → K2_max=1848 → K1_max=7392 → 1 轮           → K1=4096, K2=1024
```

**三个候选方案**：

| 方案 | M2 | K1 | K2 | K1 轮数 | ACE 效率 |
|------|-----|-----|-----|---------|----------|
| A | 128 | 2048 | 512 | 2 | 饱和 |
| B | 64 | 4096 | 1024 | 1 | 67% |
| C | 32 | 4096 | 1024 | 1 | 34% |

### 4.2 连锁推导通信模式（3D 方向，没得选）

```
K 拆给 4 行
  → B 不再沿列共享 → 各核独立 DMA + 同行 RMA 环传
  → C 是部分和 → 同列 4 行 RMA 归约
  → 跨 K1 tile 累加 → 方案 A 需要 HBM workspace（2 轮）
```

**方案 A**：B 环传 + C 归约 + workspace（2 轮），最复杂
**方案 B**：B 环传 + C 归约（1 轮），中等
**方案 C**：B 环传 + C 归约（1 轮），最简单

---

## 阶段五：理论性能建模（算总耗时，选最优）

### 5.1 先把公式里的常数定下来

```
ACE 频率 = 1.25GHz（标称，以 teco-smi 为准）
ACE 峰值 = 75 TFLOPS（@M2≥128, K2≥576）
DMA 单引擎带宽 = 40 GB/s（4KB 包，一个核独占一个引擎）
RMA 环传带宽 = 53 GB/s
RMA 归约带宽 = 53 GB/s
列广播带宽 = 278 GB/s
行广播带宽 = 188 GB/s
```

### 5.2 方案 A（M2=128, K2=512, 2 轮）

**ACE 计算**：
```
每轮计算量 = 2 × 128 × 32 × 512 = 4.19M FLOPs
ACE_cycles = 4.19M / 8192 = 512 cycles
T_ace = 512 / 1.25G = 0.41 μs
T_ace_total = 0.41 × 2 轮 = 0.82 μs
```

**DMA 访存**（每核每轮）：
```
A_tile = 128 × 512 × 2 = 128 KB
B_tile = 512 × 32 × 2  = 32 KB
C_tile = 128 × 32 × 4  = 16 KB
DMA_bytes = 128 + 32 + 16 = 176 KB/核/轮
T_dma = 176KB / 40GB/s = 4.4 μs/轮
T_dma_total = 4.4 × 2 = 8.8 μs
```

**RMA 通信**（每核每轮）：
```
B 环传：32KB / 53GB/s = 0.6 μs
C 归约：16KB × 3 份 / 53GB/s = 0.9 μs
T_rma = 0.6 + 0.9 = 1.5 μs/轮
T_rma_total = 1.5 × 2 = 3.0 μs
```

**总耗时**：
```
T_total = max(T_ace, T_dma) + T_rma
        = max(0.82, 8.8) + 3.0
        = 11.8 μs
瓶颈：DMA（8.8 μs，占 75%）
```

### 5.3 方案 B（M2=64, K2=1024, 1 轮）

**ACE 计算**：
```
每轮计算量 = 2 × 64 × 32 × 1024 = 4.19M FLOPs
ACE_cycles = 4.19M / 8192 = 512，但 M2=64 效率 67%
有效 cycles ≈ 512 / 0.67 = 764
T_ace = 764 / 1.25G = 0.61 μs
```

**DMA 访存**（每核）：
```
A_tile = 64 × 1024 × 2 = 128 KB
B_tile = 1024 × 32 × 2  = 64 KB
C_tile = 64 × 32 × 4   = 8 KB
DMA_bytes = 128 + 64 + 8 = 200 KB
T_dma = 200KB / 40GB/s = 5.0 μs
```

**RMA 通信**：
```
B 环传：64KB / 53GB/s = 1.21 μs
C 归约：8KB × 3 / 53GB/s = 0.45 μs
T_rma = 1.66 μs
```

**总耗时**：
```
T_total = max(0.61, 5.0) + 1.66 = 6.66 μs
瓶颈：DMA（5.0 μs，占 75%）
```

### 5.4 方案 C（M2=32, K2=1024, 1 轮）

**ACE 计算**：
```
计算量 = 2 × 32 × 32 × 1024 = 2.10M FLOPs
ACE_cycles = 2.10M / 8192 = 256，M2=32 效率 34%
有效 cycles ≈ 256 / 0.34 = 753
T_ace = 753 / 1.25G = 0.60 μs
```

**DMA 访存**（每核）：
```
A_tile = 32 × 1024 × 2 = 64 KB
B_tile = 1024 × 32 × 2  = 64 KB
C_tile = 32 × 32 × 4   = 4 KB
DMA_bytes = 64 + 64 + 4 = 132 KB
T_dma = 132KB / 40GB/s = 3.3 μs
```

**RMA 通信**：
```
B 环传：64KB / 53GB/s = 1.21 μs
C 归约：4KB × 3 / 53GB/s = 0.23 μs
T_rma = 1.44 μs
```

**总耗时**：
```
T_total = max(0.60, 3.3) + 1.44 = 4.74 μs
瓶颈：DMA（3.3 μs，占 70%）
```

### 5.5 方案对比

| | M2 | ACE 效率 | T_ace | T_dma | T_rma | T_total | 瓶颈 |
|---|-----|---------|-------|-------|-------|---------|------|
| A | 128 | 饱和 | 0.82 | 8.8 | 3.0 | **11.8 μs** | DMA |
| B | 64 | 67% | 0.61 | 5.0 | 1.66 | **6.66 μs** | DMA |
| C | 32 | 34% | 0.60 | 3.3 | 1.44 | **4.74 μs** ✅ | DMA |

**方案 C 胜出。** 反直觉：M2 最小、ACE 效率最低的方案反而是最快的。因为 DMA 是瓶颈，M2 小→DMA 数据量小→总耗时短。

**关键认知**：ACE 效率不是目标，T_total 才是。M2 推大只对 ACE 有利，但 DMA 数据量也同步增大。DMA 瓶颈时，M2 越小越快。

---

## 阶段六：双缓冲判定

```
T_dma = 3.3 μs, T_ace = 0.60 μs
T_dma / T_ace = 3.3 / 0.60 = 5.5 ≫ 0.8

→ 不启用双缓冲（DMA 远大于 ACE，双缓冲带不来收益）
→ 单缓冲即可，DMA 是瓶颈，优先优化 DMA
```

---

## 最终方案

| 项目 | 决策 |
|------|------|
| 拆分方式 | 3D：M/8 列 × N/8 列 × K/4 行 |
| M2 | 32 |
| K2 | 1024 |
| A 访存 | 32 核独立 DMA，无广播 |
| B 访存 | 32 核独立 DMA + 同行 RMA 环传 |
| C 访存 | 同列 4 行 RMA 归约，跨 K1 tile 无 workspace（1 轮） |
| 双缓冲 | 否 |
| 预估耗时 | 4.74 μs（DMA 瓶颈，占 70%） |

---

## 复盘：哪些是理论计算确定的，哪些不是

| 决策 | 能否理论计算确定 | 依据 |
|------|-----------------|------|
| K 要不要拆 | ✅ 能 | LDM 预算方程，K vs K_max |
| 走 2D 还是 3D | ✅ 能 | 同上 |
| M2 候选集合 | ✅ 能 | LDM 可行域 |
| 通信模式（广播/环传/归约） | ✅ 能 | 分核方案连锁推导，没得选 |
| 选哪个 M2 | ✅ 能 | 性能建模，T_total 最小的 |
| 双缓冲与否 | ✅ 能 | T_dma vs T_ace 比值 |
| 具体 tile 数值 | ✅ 能 | 对齐约束（M2%2=0, K2%32=0） |

**结论：整个过程没有"经验选择"，每一步都是算出来的。** 唯一需要外部数据的是 ACE 效率曲线（来自 ACE.xlsx 实测）和 DMA/RMA 带宽（来自硬件手册）。
