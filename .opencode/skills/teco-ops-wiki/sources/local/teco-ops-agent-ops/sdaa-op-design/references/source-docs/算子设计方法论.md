# SDAA T1 算子设计方法论

> **定位**：Agent 设计新算子的六阶段流水线。从算子特征出发，逐层推导出完整的分核+性能方案。每阶段自包含，顺序执行，不可跳步。
> **配套**：选定方案后，去 `分核.md` 查实现骨架；访存优化去 `访存与流水线优化.md`；性能数据在 `ACE.xlsx`。

---

## 阶段一：算子特征

### 目标

搞清"算什么"，输出结构化的算子描述。

### 必须回答的问题

| 问题 | 示例 |
|------|------|
| 计算模式 | 矩阵乘 / 逐元素 / 归约 / 混合 |
| Shape 范围 | M∈[1, 4096], N∈[256, 12288], K∈[256, 12288] |
| 数据依赖 | 哪些维度共享？哪些独立？有无 reduce 轴？ |
| 精度 | fp16 / bf16 / fp32 / int8 |
| 是否有 batch/head 独立维度 | 有→子网格并行，无→32 核全协作 |

### 输出

```
算子：<name>
计算：C[m,n] = Σ A[m,k] × B[k,n]   （或其他公式）
Shape：M∈[a,b], N∈[c,d], K∈[e,f]
精度：fp16×fp16→fp32
依赖：M 独立（可并行），N 独立（可并行），K 约化（需累加）
```

### 此阶段不做什么

- 不管 LDM 装不装得下
- 不选分核策略
- 不调 tile 大小

## 阶段二：硬件约束

### 目标

列出所有不可逾越的物理边界。这些是"公理"，后面所有推导都基于它们。

### 约束清单

| 约束 | 值 | 来源 | 影响 |
|------|-----|------|------|
| LDM 容量 | 235KB（可用） | 硬件固定 | 所有 buffer 的上限 |
| ACE_N | 32（锁死） | 硬件固定 | N 方向粒度不可选 |
| ACE West 口 | 128 行 | 硬件固定 | M2 上限 |
| ACE_K 粒度 | 32 | 硬件固定 | K2 必须 32 对齐 |
| ACE 频率 | SPE/2，以 `teco-smi` 为准 | 半频域 | 算力估算 |
| ACE 效率曲线 | 见 `ACE.xlsx` | 实测 | M2 和 K2 决定实际 TFLOPS |
| SPE 核数 | 32，4×8 网格 | 硬件固定 | 并行度上限 |
| DMA 引擎数 | 8，按列绑定 | 硬件固定 | 最多 8 个引擎同时服务 |
| DMA 队列深度 | ≤11 | 硬件固定 | 32 核同时 DMA 会打爆 |
| DMA 包大小 | 128B，PPU 不合并 | 硬件固定 | 小粒度搬运效率极低 |
| 列广播带宽 | 278 GB/s（@128K） | 实测 | B 列广播的天花板 |
| 行广播带宽 | 188 GB/s（对角线优化） | 实测 | A 行广播的天花板 |
| 点对点 RMA | 53 GB/s | 实测 | 环传/归约的天花板 |

### 输出

一个约束清单。后续每步推导都要对照这个清单，不违反任何一条。

## 阶段三：LDM 预算与可行域

### 目标

用 LDM 预算方程算出"哪些 tile 组合在物理上可行"。

### 步骤

**3.1 列 buffer 清单**

```
以 GEMM 2D 拆分为例：
  A_tile = M2 × K × sizeof(dtype)
  B_tile = K × 32 × sizeof(dtype)
  C_tile = M2 × 32 × sizeof(float)
```

**3.2 标份数**

```
无流水线：全都 ×1
双缓冲：  A ×2, B ×2, C ×1
Split-K： C_partial × split_num
RMA Ring：+ B_remote
```

**3.3 写方程，解 K_max(M2)**

```
LDM_used = 份数_A·M2·K·dtype + 份数_B·K·32·dtype + 份数_C·M2·32·4 ≤ 235KB

以 fp16 无双缓冲为例：
  M2·K·2 + K·32·2 + M2·32·4 ≤ 235KB
  K_max(M2) = (235×1024 - 128·M2) / (2·M2 + 64) 字节
```

**3.4 画可行域**

| M2 | K_max（无双缓冲） | K_max（双缓冲） | ACE 效率 |
|----|------------------|-----------------|----------|
| 128 | ~700 | ~350 | 饱和 |
| 64 | ~1140 | ~570 | 67% |
| 32 | ~1900 | ~950 | 34% |
| 16 | ~3100 | ~1550 | 17% |

### 输出

**关键判定**：实际 K 和 K_max(M2) 的关系。

```
K ≤ K_max(M2_target) → 2D 方向（阶段四-A）
K > K_max(M2_target) → 3D 方向（阶段四-B）
```

> M2_target 的选取原则：优先推大 M2（ACE 对 M 敏感），但也要给 K 留够空间。如果 K 太大导致 M2 被压到很小，考虑 3D 拆分。

## 阶段四：分核方案推导

### 阶段四-A：2D 方向（K 不拆）

**前提**：K ≤ K_max(M2_target)，K 可以完整放进 LDM。

**4A.1 确定 M 和 N 的拆分比例**

M/N 的比例决定网格映射。原则：**大的维度多拆，小的维度少拆**。

| M/N 特征 | 网格 | M 每核 | N 每核 | 通信 |
|----------|------|--------|--------|------|
| M 极小（≤128） | 1×32 | M | 32 | A 全核广播 |
| N 极小（≤32） | 32×1 | M/32 | N | 无广播，独立 DMA |
| N 很大（≥2048） | 2×16 | M/2 | N/16 | A 行广播 + B 独立 DMA |
| M 很大（≥4096） | 8×4 | M/8 | N/4 | A 列广播 + B 行广播 |
| 均衡 | 4×8 | M/4 | N/8 | A 行广播 + B 列广播 |

**4A.2 确定通信模式**

通信模式是网格映射的派生结果，不是独立选择：

```
M 拆给行 → A 沿行共享 → 行广播
N 拆给列 → B 沿列共享 → 列广播
M 不拆  → A 全核复制 → 一次广播
N 不拆  → B 各核独立 → 独立 DMA
```

**4A.3 确定 K 累加方式**

```
K ≤ K_max（不拆）→ accum_flag 时间分片（零通信）
K 仍太大       → Split-K 空间分片（RMA 归约）
```

### 阶段四-B：3D 方向（K 必须拆）

**前提**：K > K_max(M2_target)，K 必须拆给多核。

**4B.1 确定 K 拆分方式**

```
K 拆给 4 行 → K2 = K/4
M 拆给 8 列 → M2 = M/8（可推到 128，ACE 饱和）
N 拆给 8 列 → rma_loop 轮转
```

**4B.2 连锁推导通信模式**

K 拆了之后，通信模式是被迫推导出来的，没得选：

```
K 拆给 4 行
  → 同列 4 核的 K 段不同 → B 不再沿列共享 → 列广播不成立
  → B 必须各核独立 DMA + 同行 RMA 环传
  → C 是部分和 → 同列 4 行 RMA 归约
  → 跨 K1 tile 累加 → HBM workspace
```

**4B.3 3D vs Split-K 的权衡**

| | 3D 拆分 | Split-K |
|---|---|---|
| K 拆分方式 | 空间并行（4 行） | 时间分片 + 归约 |
| M2 | 128（ACE 饱和） | 32（受 LDM 限制） |
| ACE 效率 | 饱和 | 34% |
| B 通信 | RMA 环传 | 列广播 |
| C 通信 | RMA 归约 | RMA 归约 |
| 额外存储 | B_remote, workspace | C_partial |

选哪个？**建模算过才知道。** 进入阶段五。

### 输出

- 拆分方案：M 拆几路、N 拆几路、K 拆几路
- 通信模式：A 怎么传、B 怎么传、C 怎么归约
- 候选 tile 集合：{(M2, K2) | LDM 可行}

## 阶段五：理论性能建模

### 目标

在候选 tile 集合中，找到总耗时最短的那个。

### 模型

```
T_total = max(T_ace, T_dma) + T_rma + T_sync

其中：
  T_ace = ACE_cycles / ACE_freq
  T_dma = DMA_bytes / DMA_BW
  T_rma = RMA_bytes / RMA_BW
  T_sync = N_sync × sync_cost
```

### 5.1 ACE 拍数

从 `ACE.xlsx` 的 Cycle sheet 查表，或用公式估算：

```
ACE_cycles ≈ M2 × N2 × K2 / (128 × 32) × 2
            = M2 × K2 / 64   （N2=32 时）
```

### 5.2 ACE 端口带宽（LDM→ACE 和 ACE→LDM）

ACE 频率 = SPE/2，以 `teco-smi` 查询为准。以下带宽值基于标称 SPE=2.5GHz → ACE=1.25GHz，实际使用时等比缩放：`实际值 = 标称值 × (实际 SPE 频率 / 2.5GHz)`。

| 端口 | 方向 | 每 cycle | @1.25GHz（标称） | @1.18GHz（实际 2.36GHz） | 说明 |
|------|------|----------|-----------------|------------------------|------|
| **West（西向）** | LDM→ACE | 64B | **80 GB/s** | 75.5 GB/s | A 矩阵，列主序，加载即触发 MAC |
| **North（北向）** | LDM→ACE | 64B | **80 GB/s**（理论） | 75.5 GB/s | B 矩阵，行主序，可跨 West 行复用 |
| **写回** | ACMB→LDM | — | **27 GB/s**（fp32） | 25.5 GB/s | 双缓冲 ACMB（2×8KB），可与计算重叠 |

**North 口的等效带宽**：

North 数据可跨 West 行复用。当 West=128 行时，West 数据量 = 128×32×2B = 8KB，North 数据量 = 32×32×2B = 2KB，North 只有 West 的 1/4。因此：

```
North 等效带宽 = 80 / 4 = 20 GB/s（@West=128, fp16）
North 等效带宽 = 80 / 2 = 40 GB/s（@West=64,  fp16）
```

**写回口的摊销**：

写回是 27 GB/s 的活跃带宽，但可以被 K 维度摊销。K=384 时 12 个 ACE descriptor 共享一次写回：

```
写回摊销带宽 = 128×32×4B / (12 × ACE_cycle_time) ≈ 12.6 GB/s（@K=384）
```

half 写回（fp16 C）可进一步降低写回压力，小 K 场景下提升 20~47%。

**ACE-LDM 总带宽上限**：三个口合计约 107 GB/s（@M2=128, K2=384），需要在 LDM 读带宽上限 160 GB/s（512bit × 2.5GHz / 8）之内。

### 5.3 DMA 时间

```
DMA_bytes = 份数_A × M2 × K × 2 + 份数_B × K × 32 × 2 + C × M2 × 32 × 4
DMA_BW = 8 引擎 × 单引擎带宽

单引擎带宽：
  128B 包：~5 GB/s
  1KB 包：~20 GB/s
  4KB 包：~40 GB/s（最优）
  ≥16KB：~45 GB/s
```

**关键**：DMA 包大小取决于单次搬运量。单次 < 1KB → 效率极低。

### 5.4 RMA 通信时间

| 通信类型 | 带宽 | 数据量 |
|----------|------|--------|
| 列广播 `col_ibcast` | 278 GB/s | B_tile |
| 行广播 `row_ibcast`（对角线） | 188 GB/s | A_tile |
| 点对点 `rma_iput` | 53 GB/s | 环传/归约数据 |
| 树形归约 | 53 GB/s × log₂N | partial_data × log₂N |

### 5.5 同步开销

```
array_sync ≈ 200 cycles
row_sync   ≈ 100 cycles
col_sync   ≈ 80 cycles
```

### 5.6 搜索最优 tile

```
for each (M2, K2) in LDM 可行域:
    算 T_total(M2, K2)
    T_total = max(T_ace, T_dma, T_ace_ldm_bw) + T_rma + T_sync
    其中 T_ace_ldm_bw = ACE_LDM_bytes / 160GB/s  ← ACE 三个口的 LDM 带宽约束
选 T_total 最小的

注意：tile 要满足对齐约束
  - M2 % 2 == 0（reply=2 平分）
  - K2 % 32 == 0（ACE K 粒度）
  - N2 == 32（ACE_N 锁死）
```

### 输出

- 最优 (M2, K2)
- 预估 T_total 及各分量占比
- 瓶颈判断：计算瓶颈？DMA 瓶颈？通信瓶颈？

## 阶段六：流水线与双缓冲

### 目标

在最优 tile 确定后，用流水线掩盖延迟。

### 判定

```
T_dma < 0.8 × T_ace  → 双缓冲 A/B，DMA 被 ACE 完全掩盖
T_dma ≥ 0.8 × T_ace  → 不双缓冲，DMA 是瓶颈
T_rma < 0.8 × T_ace  → 双缓冲通信 buffer
```

### 双缓冲的 LDM 代价

```
双缓冲 → A_tile ×2, B_tile ×2 → 重新验证 LDM 预算
如果 LDM 装不下双缓冲 → 保持单缓冲，接受 DMA 开销
```

### 输出

- 是否启用双缓冲
- 修改后的 LDM 布局
- 最终预估性能
