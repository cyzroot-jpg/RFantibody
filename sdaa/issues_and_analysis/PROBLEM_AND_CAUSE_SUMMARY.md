# RFantibody 跨设备偏差 —— 问题与原因总结

## 一、说明了什么问题

**RFdiffusion 的结果不能跨设备"逐原子复现"。**

同一份代码、同一输入、同一 seed，抗体设计与 H100 参考的逐原子最大偏差：

| 平台 | ab_des_0 | ab_des_1 |
|------|----------|----------|
| A100 | 0.799 Å | 0.060 Å |
| SDAA | 10.765 Å | 2.755 Å |
| x86 CPU | 32.568 Å | 3.959 Å |

- 抗体样本偏差大且平台间差异大；纳米抗体则三平台都 ~0.02–0.12 Å（一致）；
- 即：同一个设计，换台机器跑，结果可能不同（但都是"合法设计"：靶标不动、binder 形状接近）。

## 二、什么原因

**各平台算子"舍入模式"不同（精度相同）× RFdiffusion 48 步迭代放大。**

1. **舍入模式不同（实测）**：同输入下，每个算子的 fp32 输出 SDAA ≠ A100（末位不同）——因为不同库（cuBLAS vs TecoBLAS）的分块/求和顺序/FMA 不同，而浮点不满足结合律；
2. **但精度相同（实测）**：以 float64 真值为基准，SDAA / A100 / CPU 的 fp32 误差都 ~1e-7 ~ 4e-7（都达 fp32 上限）→ **不是"谁算得不准"**；
3. **被扩散放大**：RFdiffusion 是 48 步串行去噪，微小舍入差在**敏感样本（抗体，大体系/双链/6 环）**上被放大，在**稳定样本（纳米抗体）**上被收敛；
4. **偏差大小 ≈ 平台离 H100 的数值距离**：A100 与 H100 共用 cuBLAS（最接近）→ 偏差最小；SDAA / CPU 是不同实现 → 偏差大；CPU 的 fp32 精度最差 → 偏差最大。

## 三、`export TORCH_SDAA_ALIGN_NV_DEVICE=a100` 为什么不能解决

**它只对齐"随机数（RNG）"，而病因是"算子浮点计算"。**

1. 该变量只让 `torch.randn(device='sdaa')` 与 A100 一致，**改不了算子怎么算**；
2. RFantibody 的随机性来自 **CPU 的 numpy / 无 device 的 torch**，该变量**根本碰不到**；
3. **实测**：设置后 RFdiffusion / ProteinMPNN 输出**逐字节不变** → 对本问题**无效**。

（类比：换了一模一样的食材 = 对齐 RNG，但灶不同 = 算子实现不同，菜还是不一样。）

## 四、一句话总结

> **问题**：扩散结果跨设备不可逐原子复现（抗体样本尤甚）；
> **原因**：不同平台的算子舍入模式不同（精度其实一样）被 48 步扩散放大；
> **`ALIGN_NV_DEVICE` 无效**：它只对齐随机数，管不了算子计算——要用"**同设备参考**"或"**行为化指标**"来判精度，而不是靠对齐 RNG。
