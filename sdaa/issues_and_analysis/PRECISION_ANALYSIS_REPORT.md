# RFantibody 在 SDAA 上的精度差异分析报告

> 对象：RFantibody（RFdiffusion → ProteinMPNN → RF2）在 Tecorigin SDAA 上、与 NVIDIA（H100 参考 / A100）的输出差异
> 平台：SDAA（Torch-SDAA 3.3.0，PyTorch 2.12.0，loongarch64）/ NVIDIA A100 / H100 参考
> 结论：**抗体样本的大偏差是"跨设备浮点实现差异 + 扩散采样放大"导致的数值敏感性，不是 bug。**

---

## 1. 现象

同一份代码、同一输入、同一随机种子，各模块输出与 `H100_references` 的**逐原子最大偏差**：

| 模块 / 样本 | A4000↔H100（NVIDIA 内部） | A100↔H100（CUDA） | **SDAA↔H100** |
|-------------|---------------------------|-------------------|----------------|
| RFdiffusion `nb_des_0`（纳米抗体） | 0.019 Å | 0.0133 Å | **0.0168 Å** |
| RFdiffusion `nb_des_1`（纳米抗体） | 0.074 Å | 0.1168 Å | **0.0476 Å** |
| RFdiffusion `ab_des_1`（抗体） | 0.073 Å | 0.0595 Å | **2.75 Å** |
| RFdiffusion `ab_des_0`（抗体） | **1.221 Å** | **0.799 Å** | **10.76 Å** |
| ProteinMPNN 骨架坐标 | — | 0.0 Å | 0.0 Å |
| ProteinMPNN 序列一致率 | — | 100% | 97.28% / 94.98% |
| RF2 `pred_lddt` | — | 0.90 | 0.90（参考 0.89） |

**特征**：纳米抗体、ProteinMPNN 坐标、RF2 基本一致；**只有抗体 RFdiffusion 样本偏差大**。

---

## 2. 结论（一句话）

> **SDAA 的算子（TecoBLAS/TecoDNN）与 NVIDIA（cuBLAS/cuDNN）的 fp32 绝对精度相当（都 ~1e-7 = fp32 上限），但"舍入模式"不同（不同 kernel）；RFdiffusion 是 48 步迭代扩散，会把这点差异**非线性放大**——稳定样本（纳米抗体）收敛，敏感样本（部分抗体）跑到另一个合法设计。即：不是 SDAA 算得不准，而是其 rounding 与 NVIDIA 不同。**

---

## 3. 根本原因

### 3.1 浮点实现差异（根源）
- 浮点加减**不满足结合律**（`(a+b)+c ≠ a+(b+c)`）；不同库的**求和顺序、分块、是否用 FMA** 不同 → **同一运算、不同结果**。
- 实测（`linshi/pipeline_demo/op_diff_probe64.py`，以 **float64(CPU) 为共同真值**，衡量设备 fp32 的舍入误差；跨机器可比）：

  | 算子 | Tecorigin SDAA | NVIDIA A100 | x86 CPU |
  |------|----------------|-------------|---------|
  | Linear | **1.81e-7** | 2.26e-7 | 4.15e-7 |
  | matmul / einsum | 1.70e-7 | 1.61e-7 | 3.11e-7 |
  | LayerNorm | 1.13e-7 | 1.26e-7 | 1.58e-7 |
  | softmax | 1.08e-7 | 7.87e-8 | 7.87e-8 |
  | sum(dim) | 1.29e-7 | 8.22e-8 | 1.09e-7 |
  | cdist | 4.24e-4 | 4.24e-4 | 4.74e-4 |

- **结论**：
  1. **SDAA 与 A100 的 fp32 算子精度基本一致**（都 ~1e-7 = fp32 机器精度上限）；`Linear` 上 SDAA 甚至略优于 A100；
  2. **SDAA / A100 都比 x86 CPU 的 fp32 更准**；
  3. 之前"SDAA 比 A100 差 1.5–2 倍"是**被 CPU 架构污染**（拿 A100 比 x86 CPU、SDAA 比龙芯 CPU，基准不同）造成的**假象**。
- 这不是 bug：两边都在浮点舍入误差内，且 SDAA 的**绝对精度并不比 NVIDIA 差**。

> **为何结构仍偏 13 倍**：**"绝对精度"（离真值多远）与"跨设备可复现性"（舍入模式是否与 H100 相同）是两回事**。
> A100 与 H100 共用 cuBLAS → 舍入模式几乎相同 → 输出几乎一致（0.80 Å）；SDAA 用不同 kernel → **舍入模式不同**（尽管同样"准"）→ 输出偏离更多；再经扩散**混沌非线性放大** → 差 ~13 倍。即**并非 SDAA "算得不准"，而是"rounding 方式与 NVIDIA 不同"**。

### 3.2 迭代放大（RFdiffusion 是 48 步反馈系统）
- 每步：`x_{t-1} = F(x_t)`，上一步输出喂给下一步，共 48 步；
- 若某处映射 `F` 敏感（局部雅可比大），微小扰动 `ε` 被放大 `g` 倍：`ε_final ≈ ε_0 × ∏ g_i`；
- **稳定样本** `g<1` → 误差收敛；**敏感样本** `g>1` → 指数放大到 O(Å)。

### 3.3 样本敏感性（为什么是"抗体"而非"纳米抗体"）
| 维度 | 纳米抗体 | 抗体 | 影响 |
|------|----------|------|------|
| 残基数 | ~364 | **478** | 更大 → pair/attention/图更大，累积舍入更多、岔路口更多 |
| 链 | 单链 | **H+L 双链** | 更多链间相互作用 |
| 设计 CDR 环 | 3 | **6** | 自由度更多 → 更易分叉 |
| 轨迹性质 | 稳定 | 敏感 | 决定收敛 or 放大 |

同一 run 的 `ab_des_0`(10.76) 与 `ab_des_1`(2.75) 也不同 → 敏感度是**逐轨迹**的属性。

### 3.4 平台差异大小决定放大程度
- 算子层面：SDAA 与 A100 的 fp32 **绝对精度相当**（都 ~1e-7），但**舍入模式不同**（A100/H100 共用 cuBLAS 近乎相同）；
- 结构层面：A100 偏 0.80 Å、SDAA 偏 10.76 Å（**~13 倍**）；
- 说明"**舍入模式差异 → 结构偏差**"经扩散**非线性/混沌放大**：扰动稍不同即走到完全不同的设计（分叉点效应）。

---

## 4. 为什么"只影响抗体 RFdiffusion"？——看"是否被放大"

浮点差异**处处都在**，但只有在**会被放大的环节**才显现：

| 模块 | 迭代放大？ | 离散采样？ | 结果 | 机理 |
|------|------------|------------|------|------|
| RFdiffusion 纳米抗体 | 有，但轨迹**稳定** | — | 一致 | 如"光滑的碗"，误差被收敛 |
| RFdiffusion 抗体 | 有，且轨迹**敏感** | — | 跑偏 | 如"有分叉的山坡"，误差被放大 |
| ProteinMPNN 坐标 | 无 | — | 0 Å | 骨架坐标**透传**，不重算 → 不受影响 |
| ProteinMPNN 序列 | 无 | 有（`multinomial`） | 97% | 一次采样、非迭代；仅少数"临界位点"翻转 → 影响**局部有界** |
| RF2 | recycle 但**收敛** | 无 | 0.65 Å | 预测/精修本质收敛，且无离散采样 |

**规律**：是否受影响 = 是否被放大。
- 迭代 + 敏感 → 放大（抗体扩散）；
- 迭代 + 稳定 → 收敛（纳米抗体扩散）；
- 非迭代 → 不放大（ProteinMPNN 坐标）；
- 迭代但收敛 → 影响小（RF2）；
- 离散采样 → 局部有界（ProteinMPNN 序列）。

## 5. 证据链（如何确定是"算子浮点差异"）

| # | 证据 | 结果 |
|---|------|------|
| 1 | 输入相同：随机数来自 CPU numpy/无 device 的 torch，**与设备无关**（同 seed 下各平台输入逐位一致） | 输出差异只能来自"计算" |
| 2 | **精度相同**：同输入下 SDAA 与 A100 的 fp32 误差 vs **float64 真值**（`op_diff_probe64.py`） | 都 ~1e-7（=fp32 机器精度上限）；SDAA 不比 A100 差 |
| 3 | **舍入模式不同（直接证据）**：同输入、同 seed 下逐算子输出指纹（`op_fingerprint.py`） | **每个算子的输出 SDAA ≠ A100**（末位不同），尽管两者都"准" |
| 4 | 这种差异**足以让结构跑偏**：NVIDIA 内部两套参考（A4000↔H100） | `ab_des_0` 已差 **1.22 Å**，纳米抗体仅 0.019 Å |
| 5 | 排序三平台一致：`nb < ab_des_1 < ab_des_0` | 说明是**样本属性**，非 SDAA 特有 |
| 6 | 排除 RNG：`TORCH_SDAA_ALIGN_NV_DEVICE=a100` | 输出**逐字节不变** |
| 7 | 排除建图 topk 并列 | SDAA vs CPU 边集**完全一致** |
| 8 | 排除权重/算子 bug | 权重加载 **0 偏差**；DGL 图算子/SE(3) SDAA=CPU；真 bug（`nn.Embedding`）已修 |

> **闭环**：① 精度同（vs fp64 都 ~1e-7）+ ② 同输入输出不同（指纹逐算子不同）→ 证明"**实现/舍入模式不同**"；③ 扩散混沌放大 → 敏感样本跑偏。

---

## 6. 为什么 `TORCH_SDAA_ALIGN_NV_DEVICE=a100` 解决不了

- 该变量**只对齐设备 RNG**（`torch.randn(device='sdaa')`），**改不了算子的浮点计算**；
- 且 RFantibody 的随机数来自 **CPU 的 numpy / 无 device 的 torch**，**该变量碰不到** → 实测输出**逐字节不变**；
- 根因是"**同数不同算**"，对齐"随机数（输入）"自然无效。

---

## 7. 结论与建议

**结论**：抗体样本的大偏差 = **跨设备浮点实现差异** × **48 步扩散放大** × **样本敏感性**；不是实现缺陷（真 bug 是 `nn.Embedding`，已修）。

**建议（按推荐顺序）**：
1. **为 SDAA 生成专属参考**，按官方同设备口径判精度：
   `RFANTIBODY_DEVICE=sdaa python -m test.run_tests --create-refs`
2. **改用行为化指标**（对浮点不敏感）：结构合法、CDR 标注一致、原子数一致、序列合法、RF2 分数落在合理区间。
3. **减小数值差异**（只能"更接近"）：统一为纯 fp32（关 TF32/AMP）、关键归约用高精度、差异大的算子回落 CPU / 反馈给太初优化。
4. 完全复现 NVIDIA 结果：**不可行**（跨硬件位级一致做不到）。

**正确性判据**：看"**功能一致**"而非"逐原子等于 H100"——
- 纳米抗体逐原子复现；
- RF2 `pred_lddt`/`pae` 与参考一致（SDAA 0.90 / 10.67 vs 0.89 / 10.64）；
- DGL 图算子 / SE(3) / 权重 SDAA = CPU。
