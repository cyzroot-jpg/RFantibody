# RFdiffusion 抗体样本偏差 —— 问题分析报告

> 现象：RFdiffusion 生成的**抗体**骨架，在不同计算平台（A100 / SDAA / x86 CPU）上与 H100 参考的偏差**差异极大**，且 SDAA 明显大于 A100。
> 结论：**这不是 SDAA 的 bug 或精度缺陷，而是"各平台算子舍入模式不同"被 RFdiffusion 48 步扩散在敏感样本上放大。** 证据来自三平台实测 + 分量分析 + 算子指纹 + 精度实测。

---

## 一、问题现象（数据）

### 1.1 三平台对比（同代码、同输入、同 seed，vs `H100_references`）

| 设计 | 平台 | 靶标 T 最大偏差 | **逐原子最大偏差** | 全结构 CA RMSD | binder 叠合后(形状) | binder 原始 CA |
|------|------|----------------|--------------------|----------------|---------------------|----------------|
| `ab_des_0` | **A100** | 0.015 Å | **0.799 Å** | 0.327 | 0.175 | 0.474 |
| `ab_des_0` | **SDAA** | 0.233 Å | **10.765 Å** | 5.749 | 0.960 | 8.340 |
| `ab_des_0` | **x86 CPU** | 0.192 Å | **32.568 Å** | 10.984 | 0.577 | 15.938 |
| `ab_des_1` | **A100** | 0.004 Å | **0.060 Å** | 0.011 | 0.076 | 0.016 |
| `ab_des_1` | **SDAA** | 0.126 Å | **2.755 Å** | 1.002 | 0.724 | 1.454 |
| `ab_des_1` | **x86 CPU** | 0.130 Å | **3.959 Å** | 1.384 | 0.369 | 2.007 |

**关键观察**：
1. **逐原子最大偏差排序：A100 ≪ SDAA < CPU**（ab_des_0: 0.80 < 10.77 < 32.57 Å）；
2. 偏差**随平台远离 H100 而增大**（A100 与 H100 最接近）；
3. 同一设计的**纳米抗体**（`nb_des`）三平台都极小（0.01–0.12 Å）——对照组。

### 1.2 分量分析（以 `ab_des_0` / SDAA 为例）

| 分量 | 值 | 含义 |
|------|-----|------|
| 靶标链 T 最大偏差 | 0.233 Å | **靶标几乎不动** → 坐标准确、**帧一致** |
| 全结构 CA RMSD（未叠合） | 5.749 Å | 大 |
| **binder 叠合后(形状)** | **0.960 Å** | 把 binder 对齐后，**形状差仅 ~1 Å** |

→ **大偏差主要是 binder 的"整体对接姿态（rigid-body pose）"不同，而非"折叠错误"**（叠合后形状 A100 0.175 / SDAA 0.960 / CPU 0.577 Å，都很接近）。

---

## 二、评测口径

- **指标**：逐原子最大偏差（官方 `compare_pdb_structures` 口径）= 输出与参考**逐原子配对**求坐标距离的**最大值**；
- **参考**：仓库自带 `H100_references`（官方在 H100 上跑出的标准答案）；
- 说明：这是**跨设备比对**（SDAA/CPU vs H100），用于暴露差异，**不作为 SDAA 的精度合格线**。

---

## 三、原因分析

### 3.1 不是 bug（先说排除项）

| 候选 | 实测结论 |
|------|----------|
| 随机数（RNG） | ❌ 设 `TORCH_SDAA_ALIGN_NV_DEVICE=a100` 后输出**逐字节不变** |
| 建图 topk 并列 | ❌ SDAA vs CPU 在抗体/纳米抗体输入下**边集完全一致** |
| 权重加载 | ❌ SDAA vs CPU **0 偏差** |
| 算子 bug | ❌ DGL 图算子/SE(3) SDAA=CPU；真 bug（`nn.Embedding`）已修 |
| 坐标帧/对齐 | ❌ 靶标 T 偏差 0.01–0.23 Å，帧一致 |

### 3.2 根因一：各平台算子"舍入模式"不同（直接实测）

同 seed → 同输入下，**每个算子的 fp32 输出 SDAA ≠ A100**（`op_fingerprint.py`）：

| 算子 | SDAA | A100 |
|------|------|------|
| matmul[2] | -1.650602817535e+00 | -1.650608062744e+00 |
| softmax[0] | 7.741543813609e-04 | 7.741543231532e-04 |
| cdist[0] | 9.568318724632e-03 | 3.906250000000e-03 |

> 机理：不同库（cuBLAS vs TecoBLAS）的**分块/求和顺序/FMA** 不同；浮点不满足结合律 → 同一运算**末位舍入不同**。

### 3.3 根因二：但三者"精度"相同（不差）

以 **float64 真值**为基准（`op_diff_probe64.py`）：

| 算子（rel_err vs fp64） | SDAA | A100 | x86 CPU |
|-------------------------|------|------|---------|
| Linear | 1.81e-7 | 2.26e-7 | 4.15e-7 |
| matmul | 1.70e-7 | 1.61e-7 | 3.11e-7 |
| LayerNorm | 1.13e-7 | 1.26e-7 | 1.58e-7 |

→ 都 ~1e-7（= fp32 上限）；**SDAA 不比 A100 差**；**x86 CPU 反而更差**（~3–4e-7，与其偏差最大一致）。

### 3.4 根因三：RFdiffusion 48 步迭代放大（样本敏感）

RFdiffusion 是 48 步串行去噪（每步输出喂下一步）：

| 维度 | 纳米抗体 | 抗体 |
|------|----------|------|
| 残基 / 链 / 设计环 | ~364 / 单链 / 3 | **478 / H+L 双链 / 6** |
| 轨迹性质 | **稳定（收敛）** | **敏感（放大）** |
| 结果 | 与参考一致 | 走到**另一个合法 dock** |

**样本敏感度排序三平台一致**（`nb < ab_des_1 < ab_des_0`），且 **NVIDIA 内部 A4000↔H100 在 ab_des_0 上已达 1.22 Å** → 是**样本固有敏感性**。

### 3.5 统一解释
```
不同平台/库 → 算子舍入模式不同（精度相同）
        ↓ 每算子末位差 ~1e-7
网络累积 + 48 步扩散
        ↓
敏感样本（抗体）→ 放大：差 0.8 ~ 33 Å（视平台离 H100 远近）
稳定样本（纳米抗体）→ 收敛：差 ~0.02 Å
```
**偏差大小 ≈ "该平台实现离 H100 的数值距离"**：A100(同 cuBLAS) ≪ SDAA < x86 CPU。

---

## 四、为什么 `TORCH_SDAA_ALIGN_NV_DEVICE=a100` 不行

- 该变量**只对齐随机数发生器（RNG）**，**改不了算子浮点计算**；
- 且 RFdiffusion 随机性来自 **CPU 的 numpy / 无 device 的 torch**，该变量**根本碰不到**；
- 实测设置后输出**逐字节不变** → 无效。

---

## 五、影响

| 方面 | 影响 |
|------|------|
| **适配正确性** | **无**：纳米抗体逐原子复现、RF2 分数与参考一致、图算子/SE(3)/权重 SDAA=CPU |
| **精度评测口径** | **有**：跨设备"逐原子对齐 H100"不是合格线；应用 **SDAA 专属参考** 或 **行为化指标** |
| **设计结果本身** | **基本无**：得到的是**另一个合法 dock**（靶标不动、binder 形状接近），非错误设计；扩散本就生成式、多设计筛选 |
| **跨设备可复现** | 位级不可能；**同设备可复现**（重跑逐字节相同） |
| **性能/显存** | 无 |

---

## 六、结论与建议

### 结论
1. **现象**：抗体 RFdiffusion 结果在不同平台差异大（A100≪SDAA<CPU），纳米抗体则一致；
2. **原因**：**各平台算子舍入模式不同（精度相同）× RFdiffusion 48 步扩散对敏感样本的放大**；CPU 偏差最大恰好对应其 fp32 精度最差；
3. **性质**：**不是 SDAA 的 bug、不是精度缺陷**；是跨数值环境的固有现象（NVIDIA 内部 A4000↔H100 也差 1.22 Å）。

### 建议
1. 用 **SDAA 专属参考**（`python -m test.run_tests --create-refs`）按官方同设备口径判精度；
2. 或改用**行为化指标**（结构合法 / CDR 标注 / 原子数 / 序列 / RF2 分数区间 + binder 叠合后形状）；
3. `TORCH_SDAA_ALIGN_NV_DEVICE` 对本问题无效，**不必使用**；
4. 若需对齐 NVIDIA：只能"减小算子差异"（统一纯 fp32、关键归约高精度、算子回落/反馈厂商），**无法位级一致**。
